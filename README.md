# SAR Atlas · 专利与文献证据工作台

从专利公开号、一个结构或一个靶点出发，查看专利家族、优先权日期、实施例和结构；对已整理的分子证据卡，比较结构与原始测量，并回到 PDF 核查。

项目目标是构建“竞对 SAR 演化时间线”：输入化合物、专利号或靶点，输出结构与属性变化，以及有证据支撑的研发问题假说。**当前已提供三类检索入口（其中结构检索支持精确、相似性和子结构三种方式，覆盖本地台账、ChEMBL、SureChEMBL 专利化学与 PubChem 交叉引用），以及基于已整理数据的六步 SAR 工作流：证据整理、结构对齐、可比性检查、批次汇总、证据审查和候选方向。在此之上，已建成带审计日志的类型化证据台账、供 AI agent 调用的 MCP 工具层（只能提交待确认记录、每次运行可重放）、按字段统计的抽取评测框架，以及分级抽取的控制逻辑。仍是研究原型。** 真实的专利抽取器、任意专利自动抽取和经过证据确认的历史演化路线尚未实现。

核心原则：数字只由确定性代码计算；工具与 AI 只能提交“待确认”记录，确认必须由具名的人完成；限定值、缺失值和跨来源数据不强行比较；证据不足时弃答。完整功能清单见 [FEATURES.md](FEATURES.md)，迭代进度见 [docs/iteration-plan_v1.2.md](docs/iteration-plan_v1.2.md)（原始方案 v1 见 [docs/iteration-plan.md](docs/iteration-plan.md)）。

## 当前能力

工作台顶部 **证据台账** 提供完整六步入口，默认覆盖两份论文和两份专利的 37 条结构记录、320 条观测（含缺失项）。以 `--ledger-db` 启动服务后，可把在线检索到的专利结构和 ChEMBL 测量以“待确认”状态加入台账（见下文）。详细验收与边界见 [SAR 工作流](docs/sar-workflow.md)。

| 功能 | 当前状态 |
|---|---|
| 输入完整专利公开号 | 已实现；读取 Google Patents 公共页面，支持继续检索同族和引用专利 |

| 从结构到专利 | SureChEMBL 命中可查“出现在哪些专利”；任一结构可查 PubChem 关联专利与 PubMed 文献；公开号一键核实加载；两个来源可能同源，并列显示、不当作独立佐证 |
| 靶点输入 | ChEMBL 名称 / 基因符号 / ID 查询；用户按物种与类型选择，再分页查看分子、测量及来源 |
| 专利日期与家族 | 按来源记载的优先权日排列；跨专利关联视图合并同族公开 |
| 实施例原文与化学实体索引 | 自动提取支持格式的文本和可解析结构；标题可能漏检，结构可能包含试剂与中间体 |
| 结构—实施例—活性证据卡 | 显式整理两份专利，共 6 个实施例、22 项原始测量；另有 2 项细胞测量保留未测状态 |
| A/B 分子对照 | MCS 高亮、RDKit 描述符差异；同一分子不能同时选为 A 和 B，后端拒绝相同结构对照 |
| 活性对照 | 同专利匹配协议的精确值可计算 B/A；限定值不算倍数；跨专利只并列展示原始值 |
| 跨专利关联 | 一个已整理的双家族案例，分开展示事实、研究假设和证据缺口；不认定直接演化。关系存为数据记录，带可自动核对的展示条件，不满足时说明原因 |
| 质谱校验 | 报告的 LCMS 值与转录结构比对，容差随报告精度；只能发现原子数错误，查不出同分异构与立体错误 |
| 来源文档 → 专利候选 | 解析当前测量页的真实文档，区分论文与专利；有效公开号一键核实加载，按已核实家族归组并保留来源链 |
| 候选研发程序 | 申请人匹配门槛、发明人/骨架/靶点多信号分组；完整链接合并避免链式误聚类；权重与别名可配置 |
| 骨架与 R 基团 | 证据卡的 scaffold network、共同锚点、R 片段图及分家族支持数；桥连、对称歧义、低覆盖和失败明确提示 |
| 来源追溯 | 原文/PDF 链接、实施例及表格定位、快照哈希、读取时间、当前专利证据 JSON 下载 |
| 固定文献案例 | 31 个结构的离线页面，含系列浏览、结构与测量对照、来源及验证状态 |
| 统一证据台账 | 320 条观测保留原值、限定符、实验条件、来源定位和复核缺口；可筛选及下载 |
| 台账分子对分析 | 论文与专利 A/B 的共同锚点、R 片段与歧义；逐 assay 检查暂定可比性，排除限定、重复、缺失及协议缺证项 |
| 项目目标与多性质 SAR | 选择项目目标（如改善细胞活性、同时控制外排），确认各性质对应的实验与阈值；在台账中自动找分子对（MMP），按替换并排列出各性质的有利 / 不利 / 未变 / 缺失与证据等级；不合成综合分数 |
| SAR 批次汇总 | 每批 1–8 个用户所选分子对；按核心、位点、替换方向、文档和实验分组，去重正反向对照，保留未纳入原因 |
| 证据审查 | 自动规则与人工复核分开；本机追加保存复核人、结论、理由及报告快照 |
| 候选方向 | 输入结构精确匹配本批 A 后，按具体 assay 和数值方向筛选已有 B；保留相反案例与验证计划，证据不足时弃答 |
| 类型化证据台账 | 实体与复核状态由数据模型强制；320 条观测无损迁移（还原哈希一致）；SQLite 存储与只追加审计日志；被拒绝记录只退出分析、不删除 |
| 加入台账 | 专利结构索引与 ChEMBL 测量可写入为待确认；只用服务端读取的数据，无法映射的记录说明原因 |
| AI agent 工具层 | 17 个 MCP 工具；台账只能查询与提交待确认记录；参数严格校验；每次运行留快照与记录，可逐条重放 |
| 抽取评测与分级抽取 | 按字段评测，核心指标为未标记错误数；分级抽取控制逻辑（页面分区、逐级调用、冲突保留、置信度）已就绪，真实抽取器尚未接入 |

## 快速开始

### 在 GitHub 上运行（不用在本地拉代码）

- **工作台（GitHub Codespaces）**：在仓库页面切到 `codex/sar-evidence-pipeline` 分支，点 **Code → Codespaces → Create codespace on codex/sar-evidence-pipeline**。首次创建会自动安装依赖（几分钟），随后自动启动服务并在浏览器打开 8766 端口的转发地址；也可以在 **Ports** 标签里点 8766 的地址打开。配置见 [.devcontainer/](.devcontainer/)。Codespace 可以联网，专利检索、ChEMBL、SureChEMBL、PubChem 都能直接用。
  - 转发地址默认是**私有**的，只有登录 GitHub 的你能打开。要给化学家看，可在 Ports 标签把 8766 设为 Public，演示结束后改回 Private 并停止 Codespace：公开期间，拿到链接的人都能使用检索和“加入台账（待确认）”。
  - 服务仍只监听 127.0.0.1，只额外接受这个 Codespace 自己的转发地址（`--public-host`，由 `.devcontainer/start.sh` 自动填写）。
- **在线核对（GitHub Actions）**：仓库的 **Actions → Online path check → Run workflow**。在 GitHub 的运行器上执行 `python -m phase0.tools.verify_online`，结果显示在该次运行的摘要页，`report.md` / `report.json` 可在 Artifacts 中下载。外部服务可能对云端运行器限流，失败时先看报告里的具体原因。

### 在本机运行

需要 Python 3.10+，以下命令在仓库根目录执行。常规工作台和离线案例不需要模型 API key。

```sh
python -m venv .venv
```

激活环境：

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

```sh
# macOS / Linux
source .venv/bin/activate
```

安装依赖并启动：

```sh
python -m pip install -r requirements.txt
python -m phase0.sar.serve --port 8766
```

看到 `Open http://127.0.0.1:8766` 后打开 [本机工作台](http://127.0.0.1:8766/)（新版界面，见下节；原界面在 [/classic](http://127.0.0.1:8766/classic)，六步工作流在 [/classic/evidence](http://127.0.0.1:8766/classic/evidence)）。服务只绑定本机，运行服务的终端窗口要保持打开；浏览器提示“拒绝连接”（`ERR_CONNECTION_REFUSED`）说明服务没有在运行，或端口不是 8766。

可选：

```sh
python -m phase0.sar.serve --port 8766 --ledger-db artifacts/ledger.sqlite   # 启用台账数据库与“加入台账”
python -m pip install -r requirements-agent.txt                              # AI agent 工具层（MCP）依赖
python -m pip install -r requirements-browser.txt                            # 浏览器测试（Playwright）依赖
python -m phase0.tools.verify_online                                         # 在可联网的机器上核对在线路径
```

### 新版工作台（按 `重构原型/` 设计稿）

首页一个输入框自动识别专利公开号、SMILES、靶点名称或 ChEMBL ID；结果和已整理证据都汇入**调研**（一组台账文档加上目标与署名判断，保存在 `artifacts/studies.json`；不存在时提供预置示例“ALK 大环系列 · 辉瑞”）。调研内的数字一律在请求时从证据台账读取，调研本身不保存证据。

| 页面 | 内容 |
|---|---|
| 首页 `/` | 统一搜索与类型识别、拖入 PDF 入口、我的调研（结构记录 / 观测 / 已确认数）、示例数据集 |
| 结构检索 `/search` | 本机 RDKit 解析预览、匹配方式与阈值、检索范围（联网来源需勾选，并说明发送什么）、标准化；结果页含检索覆盖报告、按专利 / 论文分组、调研归属、SureChEMBL 所在专利与 PubChem 交叉引用，可把台账文档加入调研 |
| 从 PDF 开始 `/upload` | 在浏览器内计算 SHA-256，与台账已收录的公开 PDF 比对，文件名只作推测；页面分区与抽取步骤明确标为未接入（I3a / I3b） |
| 概览 | 家族数与优先权范围、台账范围、项目目标、具名确认数；家族时间线；下一步（补测建议第 1 位、默认阈值待确认、待复核）；跨家族关系的事实 / 假设 / 缺口 |
| 证据 | 按文档分组的结构—测量表：L0–L3 来源等级与复核状态筛选、nM / p 值切换、子结构筛选；色阶只在同一文档同一实验列内、只用于精确 nM 值；限定值虚线框、未测不填零；勾选 A/B 进入对照 |
| SAR 分析 | 项目目标与先导结构、必须保留片段、实验映射（方向、阈值、区间、实验勾选）→“确认映射并重新分析”保存到调研；按替换 / 按位点的多性质表与分子对明细；补测建议；审查与署名 |
| 时间线与程序 | 按优先权日的家族时间轴与引用箭头；已整理实施例的 R 基团对齐（与同家族上一行不同的位点标黄）；“为什么归为一组”需读取公开页面后计算 |
| 对照 | MCS 差异高亮、活性（同一文档给出 B/A 数值比；跨文档只并列原始值）、RDKit 性质差、署名“研究假设”或“证据缺口” |
| 报告 | 结论摘要（由人撰写）、家族时间线、关键对照、SAR 讨论材料、事实 / 假设 / 缺口与全部署名判断、证据来源附录与快照哈希；导出 PDF（浏览器打印）、Markdown、JSON |
| 复核队列 `/review` | 按来源类别列出待确认记录，原文页按需加载；逐项核对清单、质谱校验、具名复核人与理由；确认连同其测量写入台账（L3），拒绝只退出分析不删除；快捷键 J / K / Y |

### 六步 SAR 工作流（经典界面）

启动服务后打开 [证据台账](http://127.0.0.1:8766/classic/evidence)，或在经典界面顶部点击同名链接。

1. **① 整理证据**：筛选文档、分子或实验，查看原始记录和待补证据。
2. **② 结构对齐**：选定来源及不同的 A/B 分子，点击“分析结构变化”。
3. **③ 可比性检查**：点击“检查所选分子的测量”，查看暂定 B/A 或不计算原因。
4. **④ SAR 汇总**：点击“加入当前已检查分子对”；可继续添加其他对照，每批最多 8 对，再点击“汇总本批替换效果”。
5. **⑤ 证据审查**：查看自动阻断与缺口；填写复核人、结论和理由，保存人工记录。
6. **⑥ 改造建议**：输入 SMILES 或点击“填入当前 A”，选择具体实验和期望数值方向，生成已有分子的候选方向，可下载完整结果。

推荐案例：来源 `CHEMBL3286195`，A 选 **6f**、B 选 **6e**，完成②至⑤；⑥选择 `CHEMBL3293161` 和“数值降低”。同一替换在 `CHEMBL3293391`（MDR1 外排比，MDCK 细胞）下数值升高，即酶活性有利、外排不利，不能据单个终点认定整体更优。

批次保存在页面会话中，刷新会清空；请下载 JSON 留档。人工复核及报告快照保存在 `artifacts/sar-reviews/<report_id>/`，不提交 Git。重新选择同一批证据并汇总可读取对应复核记录；证据变化后不沿用旧记录。最新复核为“拒绝”或“待补证据”时暂停候选输出。

**适用边界**：数值变化不代表统计显著性、单一基团因果效果或真实优化顺序。自动审查不等于化学家复核，人工接受也不清除原始数据缺口。建议仅限本批中与输入 A 精确匹配的已记录 A→B 替换，不外推到任意新骨架或预测未实测 ADMET。当前所有数据仍待独立复核，论文原图/表格定位尚未逐项补齐。

### 项目目标与多性质 SAR（经典界面 `/classic/project`）

从工作台顶部的“项目目标”或 `/evidence` 页面进入：

1. 选择目标模板（例如“改善细胞活性，同时控制外排”），可填写靶点关键词（如 `ALK`），点“生成实验映射建议”。
2. 逐项核对每个性质对应的实验、方向（越低越好 / 越高越好 / 目标区间 / 仅参考）和阈值；目标区间如外排比 ≤ 2.5、LogD 1–3，向区间靠近记为有利。也可以移除性质，或点“添加自定义性质”从任意实验组成新性质（如微粒体清除率）。阈值默认活性与比值按 2 倍、LogD 按差值 0.5，标注“默认值，待化学家确认”，修改后记为用户设定。
3. 点“确认映射并分析”：系统用 MMP 在台账中自动找分子对，每个性质按实验逐项比较（只比同一文档内的实验，限定值、重复、缺失不计算），按替换或按位点（连接点 3 个键以内的化学环境，可跨文档归并同一位置）汇总并给出证据等级，列出目标性质缺失的分子对。

案例：替换 `C[*:1]>>[H][*:1]` 中，6f → 6e 的酶 Ki 有利（B/A 0.127），MDR1 外排比不利（B/A 2.24），LogD 未变，6f 没有细胞 IC50 记录。结果页还给出：各性质在范围内的覆盖；每种替换的分类（候选方向 / 取舍 / 不利 / 证据不足）；按固定规则排序的补测建议（本例第一条是 6f 的细胞 IC50，可同时判断 6f → 6d 与 6f → 6e）；候选与取舍的合成可行性待评估项（只是提示，不做判断）。可下载 Markdown 讨论材料（每个数字附实验与观测编号）和完整 JSON。输出是讨论材料，不是结论。

### 专利检索体验流程（经典界面 `/classic`）

1. 点击 **加载跨家族证据案例**，读取两份公开专利并进入“跨专利关联”。首次读取需要联网。
2. 查看按优先权日排列的两个家族，以及关联事实、研究假设和缺少的证据。
3. 点击 **对照早期 Example 7 与大环 Example 6 →**，查看结构差异与原始活性值。
4. 切换到 **分子证据卡**，自行选择不同分子为 A、B；底部选择栏显示当前分子，点击 **查看 A/B 对照 →** 后计算。
5. 点击结构图、活性表的来源链接，核对原始 PDF；在“家族与来源”下载当前专利的证据 JSON。

也可以在输入框直接填写完整公开号，例如 `WO2013132376A1`。其他专利可检索文本和结构索引，但只有已整理且来源匹配的专利才有证据卡，不会按结构索引顺序编造实施例映射。

原始 HTML、SHA-256、读取时间及解析 JSON 缓存在 `artifacts/patent-cache/`，后续请求优先使用缓存，**不会自动保证上游内容为最新版本**。网络、校验或解析失败会显示错误，不用样例替代。来源 HTML 哈希改变时，旧证据映射停用并等待重新核对。原始 HTML/PDF 缓存不提交到仓库。

### 结构检索与靶点入口（经典界面 `/classic`）

输入框左侧可切换“专利号 / SMILES / 靶点”。

- **SMILES（结构检索）**：粘贴结构或点击“填入洛拉替尼 SMILES”，选择检索方式后检索：
  - **精确**：按标准 InChIKey，同时匹配已整理的专利证据卡；
  - **相似性**：Morgan 指纹（半径 2、2048 位）Tanimoto，阈值 40–100%，默认 70%；相似度只用于排序和筛选，不说明活性相近、属于同一研发程序或被某专利覆盖；
  - **子结构**：输入片段 SMILES，至少 6 个重原子，避免命中过多。

  示例（已整理的 ALK 案例）：以洛拉替尼做相似性检索，阈值降到 50% 也只能找到同一篇论文里的类似物，找不回早期无环专利家族（大环化后 Morgan 相似度只有 0.19–0.27）；改用两个家族共有的片段 `Nc1ncccc1OCc1ccccc1` 做子结构检索，两个家族的实施例全部找回。**相似度适合找类似物，找骨架变化较大的跨系列关联时请用子结构检索。**

  默认先标准化（去盐和溶剂、中和、统一互变异构形式；子结构查询不做互变异构），页面显示实际做了哪些改动，并可关闭。默认只检索本地证据台账（范围与命中数一并显示）；勾选“同时查询 ChEMBL”或点击结果中的查询按钮后，才向 ChEMBL 发送标准 InChIKey（精确）或标准化后的 SMILES（相似性、子结构）。ChEMBL 命中逐个用本地 RDKit 复核，复现不了的标红提示而不删除；返回被截断时明确提示；未命中不代表不存在。命中分子可继续查看测量、来源文档和专利候选。

  勾选“同时查询 SureChEMBL”后，另在 SureChEMBL（专利中自动提取的化学结构）中检索。检索是服务端异步任务，可能需要一两分钟；每次取前 20 个命中，按所选阈值再过滤并显示过滤数量，同样逐个用 RDKit 复核。点“查看含此化合物的专利”可列出它出现在哪些专利中，公开号可一键“核实并加载专利”进入专利工作台。SureChEMBL 命中只说明结构出现在专利文本或图像中，不说明是实施例或被权利要求覆盖；数据为 CC BY 4.0，页面署名并保留 SCHEMBL 编号。接口行为依据第三方实测记录，本项目尚未实连，核实记录见 [docs/surechembl-access.md](docs/surechembl-access.md)。

  每次结构检索都附“检索覆盖报告”：各来源是否查询、命中与显示数量、是否截断、本地命中的文档分布，以及已知缺口（如只有结构没有测量、未覆盖商业数据库）。SureChEMBL 命中的专利列表里，可把该化合物作为该专利的结构“加入台账（待确认）”：服务端重新读取化合物并核对专利关联，角色记为未指定，不带测量。

  检索结构、ChEMBL 命中和 SureChEMBL 命中旁都有“PubChem 专利与文献”按钮：按标准 InChIKey 查 PubChem 登记的关联专利与 PubMed 文献（各前 20 条附总数），已整理证据包中的专利排在最前，公开号可一键核实加载。PubChem 的专利关联与 SureChEMBL 可能同源，两者并列显示、不合并，也不当作相互独立的佐证。每次最多 3 个请求，远低于 PubChem 的限速；接口未经本项目实连，核实记录见 [docs/pubchem-access.md](docs/pubchem-access.md)。
- **靶点**：输入 `ALK`、`EGFR` 等名称/基因符号，或 `CHEMBL4247` 等 ID，查询 ChEMBL。先选择候选的物种和靶点类型，再查看测量。人源 ALK 另提供已整理双家族案例入口，不代表该靶点的完整专利清单。
- **测量结果**：每页最多 20 条，按 activity_id 排列，可翻页；保留限定符、缺失值和质量标记，附 activity、assay、document 原始响应链接。可将记录中的 SMILES 再用于本地证据检索。不同协议不自动合并，也不按返回顺序认定药效强弱。

靶点候选最多展示 20 项，过多时请细化名称或使用 ID。SMILES 限制为 2000 字符 / 200 个原子；测量最多浏览前 10020 条，界面显示来源总数。ChEMBL 响应缓存在 `artifacts/discovery-cache/`，记录哈希和读取时间；缓存不代表最新数据库内容。在线失败与零命中分开提示，SMILES 查询失败时可保留本地结果。依据 [ChEMBL 官方接口说明](https://chembl.gitbook.io/chembl-interface-documentation/web-services/chembl-data-web-services) 实现。

结构命中、数据库中的专利关联与专利实施例证据是不同层次；新入口尚不能自动从任意分子或靶点生成完整竞对专利路线。

## 证据台账与“加入台账”

台账以 pydantic 定义文档、化合物、实验、观测、文档关系和复核状态：化合物角色必填；缺失分为未测、空白、未报告、不适用，均不能带数值；限定符原样保留；分级值须在实验中定义。已提交的 320 条观测迁入后，还原结果与原台账的规范化 SHA-256 完全一致。

```sh
python -m phase0.ledger.migrate                                  # 构建类型化台账并核对无损
python -m phase0.ledger.store init --db artifacts/ledger.sqlite  # 建库
python -m phase0.ledger.store status --db artifacts/ledger.sqlite
```

存储为 SQLite，审计日志只追加。工具只能提交 `proposed` 记录、不能覆盖；确认或拒绝必须写明复核人和理由；被拒绝的记录留在库中，只从分析视图排除。以 `--ledger-db` 启动服务后，专利信息栏和 ChEMBL 测量页各有“加入台账（待确认）”按钮：页面只传“哪一页、哪几条”，数值由服务端从自己的缓存重新读取；限定符缺失、文档类型未确认、缺少结构等记录不写入并说明原因。说明见 [phase0/ledger/README.md](phase0/ledger/README.md)。


尚未实现的产品能力包括：真实的专利抽取器（通用 PDF 结构 OCR、任意活性表自动抽取；控制逻辑已就绪）、商业库导出导入、自动跨专利路线与经证据确认的研发意图。当前索引最多显示 120 个有效结构；OCR 标题漏检和结构解析失败不表示原文不存在对应内容。未测量脑暴露、选择性或毒性时，不对这些方向作结论。

## 从检索结果追溯来源文档和专利

在分子或靶点的测量结果中点击“解析本页来源文档与专利候选”。服务重新读取该查询页的测量关联，按 ChEMBL 文档 ID 去重并查询文档元数据。卡片区分论文、专利、其他及待核实文档，展示标题、作者、年份、期刊、摘要和 DOI / PubMed（有数据时）。

仅当文档类型为 PATENT 且 patent_id 可解析为完整公开号时，提供“核实并加载专利”。不会从论文标题猜测专利，不补猜 A1/B2 后缀。加载失败保留待核实候选；加载成功进入现有专利工作台，并按原始专利页面的家族 ID 归组。同族公开及各自的来源链仍保留，家族缺失时不强行合并。

“为什么找到这份文档 / 专利”可展开查看入口、分子或靶点 ID、关联测量、文档和查询快照。加载后的“家族与来源”及下载的专利 JSON 也保留来源链。候选来自当前浏览会话中已解析的测量页，不是全库专利清单，刷新页面会清空会话候选。没有专利命中与文档服务失败明确区分，不返回固定案例。

接口：`POST /api/discover`，请求示例 `{"mode":"documents","entity":"target","id":"CHEMBL4247","offset":0}`；复用活动查询的分页限制，每次最多解析当前页 20 条测量涉及的文档。此关联不等于实施例映射、专利权利要求覆盖或研发演化证明。

## 候选研发程序与 R 基团对齐

加载专利后打开 **程序与 R 基团 → 分析已加载专利**。页面展示家族分组、规范化申请人、发明人、标题/摘要中的靶点提及，以及每一对家族的信号、分数和未合并原因。点击组内对齐，或勾选家族进行手动结构比较，可查看共同锚点、每个实施例的 R 片段图、桥连片段和按家族去重的支持数；结果可下载 JSON，保留原文定位、输入快照和配置。

- 聚类参数在 `phase0/data/program_analysis.yaml`。目前别名表显式收录 Pfizer 名称变体，不自动推断未知子公司关系。靶点是可配置词典在标题/摘要中的提及，不是已验证靶点作用。
- 发明人 / 骨架 / 靶点权重为 0.35 / 0.40 / 0.25，候选阈值 0.55，均为未校准启发式参数。申请人必须匹配，缺失信号不重新分配权重，至少两个信号支持且双方具备证据结构才可合并。组间合并要求全部跨组配对通过，优先权日期不参与打分。
- 骨架信号优先使用网络节点集合 Jaccard；当共享至少两个非通用环系时，允许用更高的环系 Jaccard 补充，以免大环化导致完整骨架不一致。单独共享苯环不触发该补充。方法和两种分数均在结果中保留，未经大规模外部验证。
- 对齐从 Murcko 骨架网络选择覆盖所有输入分子的最大共同节点，并在严格元素/键型 MCS 给出更大完整结果时使用后者。MCS 与 R-group 分解各设置 3 秒限制；超时或无法分解不生成虚构位点。低于 60% 的覆盖仅提示局部对齐，不自动认定骨架跃迁。
- R 标签只在本次对齐中有效，可能存在对称歧义，不等于专利 R 编号。多连接点片段会标记为桥连，不能分别认作多个单点替换。不同日期家族的片段差异只描述已整理样本，不据此判定探索终止或优化因果；未完整分析立体变化及杂原子替换。
- 单次最多 16 份专利、36 张证据卡；排除多组分和超过 100 重原子的结构。索引结构不参与程序骨架信号和 R 分解，未整理实施例的家族可能保持未归组。当前六张专利卡仍待独立化学家复核；这不是全库自动程序重建或科学验收完成。

实现位于 `phase0/sar/programs.py`、`phase0/sar/scaffolds.py` 与 `phase0/web/programs.js`。使用 [RDKit scaffold network](https://www.rdkit.org/docs/source/rdkit.Chem.Scaffolds.rdScaffoldNetwork.html) 和 [R-group decomposition](https://www.rdkit.org/docs/source/rdkit.Chem.rdRGroupDecomposition.html)。
