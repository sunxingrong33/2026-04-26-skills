# SAR Atlas · 专利与文献证据工作台

从专利公开号出发，查看专利家族、优先权日期、实施例和结构；对已整理的分子证据卡，比较结构与原始测量，并回到 PDF 核查。

项目目标是构建“竞对 SAR 演化时间线”：输入化合物、专利号或靶点，输出结构与属性变化，以及有证据支撑的研发问题假说。**当前已提供三类检索入口，以及基于已整理数据的六步 SAR 工作流：证据整理、结构对齐、可比性检查、批次汇总、证据审查和候选方向。在此之上，已建成带审计日志的类型化证据台账、供 AI agent 调用的 MCP 工具层（只能提交待确认记录、每次运行可重放）、按字段统计的抽取评测框架，以及分级抽取的控制逻辑。仍是研究原型。** 真实的专利抽取器、任意专利自动抽取和经过证据确认的历史演化路线尚未实现。

核心原则：数字只由确定性代码计算；工具与 AI 只能提交“待确认”记录，确认必须由具名的人完成；限定值、缺失值和跨来源数据不强行比较；证据不足时弃答。完整功能清单见 [FEATURES.md](FEATURES.md)，迭代进度见 [docs/iteration-plan.md](docs/iteration-plan.md)。

## 当前能力

工作台顶部 **证据台账** 提供完整六步入口，默认覆盖两份论文和两份专利的 37 条结构记录、320 条观测（含缺失项）。以 `--ledger-db` 启动服务后，可把在线检索到的专利结构和 ChEMBL 测量以“待确认”状态加入台账（见下文）。详细验收与边界见 [SAR 工作流](docs/sar-workflow.md)。

## 快速开始

需要 Python 3.10+，以下命令在仓库根目录执行。常规工作台和离线案例不需要模型 API key。

```sh
python -m venv .venv
```

激活环境：

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

```sh
# macOS / Linux
source .venv/bin/activate
```

安装依赖并启动：

```sh
python -m pip install -r requirements.txt
python -m phase0.sar.serve --port 8766
```

打开 [本机工作台](http://127.0.0.1:8766/)。服务只绑定本机，关闭服务后页面接口不可用。

可选：

```sh
python -m phase0.sar.serve --port 8766 --ledger-db artifacts/ledger.sqlite   # 启用台账数据库与“加入台账”
python -m pip install -r requirements-agent.txt                              # AI agent 工具层（MCP）依赖
```

### 六步 SAR 工作流

启动服务后打开 [证据台账](http://127.0.0.1:8766/evidence)，或点击工作台顶部同名链接。

1. **① 整理证据**：筛选文档、分子或实验，查看原始记录和待补证据。
2. **② 结构对齐**：选定来源及不同的 A/B 分子，点击“分析结构变化”。
3. **③ 可比性检查**：点击“检查所选分子的测量”，查看暂定 B/A 或不计算原因。
4. **④ SAR 汇总**：点击“加入当前已检查分子对”；可继续添加其他对照，每批最多 8 对，再点击“汇总本批替换效果”。
5. **⑤ 证据审查**：查看自动阻断与缺口；填写复核人、结论和理由，保存人工记录。
6. **⑥ 改造建议**：输入 SMILES 或点击“填入当前 A”，选择具体实验和期望数值方向，生成已有分子的候选方向，可下载完整结果。

推荐案例：来源 `CHEMBL3286195`，A 选 **6f**、B 选 **6e**，完成②至⑤；⑥选择 `CHEMBL3293161` 和“数值降低”。该案例在另一实验 `CHEMBL3293391` 下数值方向相反，不能据单个终点认定整体更优。

批次保存在页面会话中，刷新会清空；请下载 JSON 留档。人工复核及报告快照保存在 `artifacts/sar-reviews/<report_id>/`，不提交 Git。重新选择同一批证据并汇总可读取对应复核记录；证据变化后不沿用旧记录。最新复核为“拒绝”或“待补证据”时暂停候选输出。

**适用边界**：数值变化不代表统计显著性、单一基团因果效果或真实优化顺序。自动审查不等于化学家复核，人工接受也不清除原始数据缺口。建议仅限本批中与输入 A 精确匹配的已记录 A→B 替换，不外推到任意新骨架或预测未实测 ADMET。当前所有数据仍待独立复核，论文原图/表格定位尚未逐项补齐。

### 专利检索体验流程

1. 点击 **加载跨家族证据案例**，读取两份公开专利并进入“跨专利关联”。首次读取需要联网。
2. 查看按优先权日排列的两个家族，以及关联事实、研究假设和缺少的证据。
3. 点击 **对照早期 Example 7 与大环 Example 6 →**，查看结构差异与原始活性值。
4. 切换到 **分子证据卡**，自行选择不同分子为 A、B；底部选择栏显示当前分子，点击 **查看 A/B 对照 →** 后计算。
5. 点击结构图、活性表的来源链接，核对原始 PDF；在“家族与来源”下载当前专利的证据 JSON。

也可以在输入框直接填写完整公开号，例如 `WO2013132376A1`。其他专利可检索文本和结构索引，但只有已整理且来源匹配的专利才有证据卡，不会按结构索引顺序编造实施例映射。

原始 HTML、SHA-256、读取时间及解析 JSON 缓存在 `artifacts/patent-cache/`，后续请求优先使用缓存，**不会自动保证上游内容为最新版本**。网络、校验或解析失败会显示错误，不用样例替代。来源 HTML 哈希改变时，旧证据映射停用并等待重新核对。原始 HTML/PDF 缓存不提交到仓库。

### SMILES 与靶点入口

输入框左侧可切换“专利号 / SMILES / 靶点”。

- **SMILES**：粘贴结构或点击“填入洛拉替尼 SMILES”，然后检索。默认只在本地解析并匹配已整理的专利证据卡；勾选“同时查询 ChEMBL”或点击结果中的查询按钮后，才向 ChEMBL 发送标准 InChIKey。命中记录后可查看相关测量与靶点。本地匹配保留立体信息；标准 InChIKey 可能合并互变异构形式，当前未做相似性、子结构或去盐检索。
- **靶点**：输入 `ALK`、`EGFR` 等名称/基因符号，或 `CHEMBL4247` 等 ID，查询 ChEMBL。先选择候选的物种和靶点类型，再查看测量。人源 ALK 另提供已整理双家族案例入口，不代表该靶点的完整专利清单。
- **测量结果**：每页最多 20 条，按 activity_id 排列，可翻页；保留限定符、缺失值和质量标记，附 activity、assay、document 原始响应链接。可将记录中的 SMILES 再用于本地证据检索。不同协议不自动合并，也不按返回顺序认定药效强弱。

靶点候选最多展示 20 项，过多时请细化名称或使用 ID。SMILES 限制为 2000 字符 / 200 个原子；测量最多浏览前 10020 条，界面显示来源总数。ChEMBL 响应缓存在 `artifacts/discovery-cache/`，记录哈希和读取时间；缓存不代表最新数据库内容。在线失败与零命中分开提示，SMILES 查询失败时可保留本地结果。依据 [ChEMBL 官方接口说明](https://chembl.gitbook.io/chembl-interface-documentation/web-services/chembl-data-web-services) 实现。

结构命中、靶点测量关联与专利实施例证据是不同层次；新入口尚不能自动从任意分子或靶点生成完整竞对专利路线。

## 证据台账与“加入台账”

台账以 pydantic 定义文档、化合物、实验、观测、文档关系和复核状态：化合物角色必填；缺失分为未测、空白、未报告、不适用，均不能带数值；限定符原样保留；分级值须在实验中定义。已提交的 320 条观测迁入后，还原结果与原台账的规范化 SHA-256 完全一致。

```sh
python -m phase0.ledger.migrate                                  # 构建类型化台账并核对无损
python -m phase0.ledger.store init --db artifacts/ledger.sqlite  # 建库
python -m phase0.ledger.store status --db artifacts/ledger.sqlite
```

存储为 SQLite，审计日志只追加。工具只能提交 `proposed` 记录、不能覆盖；确认或拒绝必须写明复核人和理由；被拒绝的记录留在库中，只从分析视图排除。以 `--ledger-db` 启动服务后，专利信息栏和 ChEMBL 测量页各有“加入台账（待确认）”按钮：页面只传“哪一页、哪几条”，数值由服务端从自己的缓存重新读取；限定符缺失、文档类型未确认、缺少结构等记录不写入并说明原因。说明见 [phase0/ledger/README.md](phase0/ledger/README.md)。

## AI agent 工具层（MCP）

```sh
python -m pip install -r requirements-agent.txt
python -m phase0.tools.demo                                              # 离线演示：脚本化会话 + 重放
python -m phase0.tools.mcp_server all --ledger-db artifacts/ledger.sqlite  # stdio MCP 服务
python -m phase0.tools.replay artifacts/runs/<run_id>                    # 按运行记录重放
```

12 个工具覆盖台账查询与提交、结构性质、质谱校验、可比性检查与骨架对齐、专利与 ChEMBL 读取。**没有确认、拒绝、导入工具**；agent 的写入记为本次运行并附依据。参数先按签名校验，拼错的参数名直接报错而不是被静默忽略。每次运行保存开始时的台账快照与调用记录，重放时在快照副本上逐条重新执行（包括写入）并比对结果，禁止联网。尚未用真实模型端到端运行 agent。说明及 `.mcp.json` 配置示例见 [phase0/tools/README.md](phase0/tools/README.md)。

## 抽取评测与分级抽取

```sh
python -m phase0.eval.extraction_metrics --pred <预测目录>   # 按字段评测
python -m phase0.extract.demo                                # 离线演示：模拟抽取器 + 抽取报告 + 评测
```

评测按字段统计，核心指标是**未标记错误数**（抽错却未标为低置信度）、编造数值数和可比性误判数。金标准 v0 由现有两份专利证据包派生，待独立复核；标注格式见 [phase0/data/gold/README.md](phase0/data/gold/README.md)。

分级抽取控制逻辑按“结构化记录 → 专利全文 → PDF 图表识别”逐级调用注入的抽取器：只把缺失的必填字段交给下一级，齐全后不再调用后续级别；抽取结果须带来源上的公开号和实施例编号，否则拒绝；各级不一致时保留冲突；用质谱和可选的名称转结构交叉校验，多路独立证据一致才评为高置信度。输出金标准格式预测、待确认的台账记录和复核用抽取报告。**真实抽取器尚未接入，因此还没有真实抽取准确率**；两个来源给出同一错误同分异构体时仍会评为高置信度，已写成测试。说明见 [phase0/extract/README.md](phase0/extract/README.md)。

## 验证与科学边界

## 从检索结果追溯来源文档和专利

在分子或靶点的测量结果中点击“解析本页来源文档与专利候选”。服务重新读取该查询页的测量关联，按 ChEMBL 文档 ID 去重并查询文档元数据。卡片区分论文、专利、其他及待核实文档，展示标题、作者、年份、期刊、摘要和 DOI / PubMed（有数据时）。

仅当文档类型为 PATENT 且 patent_id 可解析为完整公开号时，提供“核实并加载专利”。不会从论文标题猜测专利，不补猜 A1/B2 后缀。加载失败保留待核实候选；加载成功进入现有专利工作台，并按原始专利页面的家族 ID 归组。同族公开及各自的来源链仍保留，家族缺失时不强行合并。

“为什么找到这份文档 / 专利”可展开查看入口、分子或靶点 ID、关联测量、文档和查询快照。加载后的“家族与来源”及下载的专利 JSON 也保留来源链。候选来自当前浏览会话中已解析的测量页，不是全库专利清单，刷新页面会清空会话候选。没有专利命中与文档服务失败明确区分，不返回固定案例。

接口：`POST /api/discover`，请求示例 `{"mode":"documents","entity":"target","id":"CHEMBL4247","offset":0}`；复用活动查询的分页限制，每次最多解析当前页 20 条测量涉及的文档。此关联不等于实施例映射、专利权利要求覆盖或研发演化证明。

## 候选研发程序与 R 基团对齐

加载专利后打开 **程序与 R 基团 → 分析已加载专利**。页面展示家族分组、规范化申请人、发明人、标题/摘要中的靶点提及，以及每一对家族的信号、分数和未合并原因。点击组内对齐，或勾选家族进行手动结构比较，可查看共同锚点、每个实施例的 R 片段图、桥连片段和按家族去重的支持数；结果可下载 JSON，保留原文定位、输入快照和配置。

- 聚类参数在 `phase0/data/program_analysis.yaml`。目前别名表显式收录 Pfizer 名称变体，不自动推断未知子公司关系。靶点是可配置词典在标题/摘要中的提及，不是已验证靶点作用。
- 发明人 / 骨架 / 靶点权重为 0.35 / 0.40 / 0.25，候选阈值 0.55，均为未校准启发式参数。申请人必须匹配，缺失信号不重新分配权重，至少两个信号支持且双方具备证据结构才可合并。组间合并要求全部跨组配对通过，优先权日期不参与打分。
- 骨架信号优先使用网络节点集合 Jaccard；当共享至少两个非通用环系时，允许用更高的环系 Jaccard 补充，以免大环化导致完整骨架不一致。单独共享苯环不触发该补充。方法和两种分数均在结果中保留，未经大规模外部验证。
- 对齐从 Murcko 骨架网络选择覆盖所有输入分子的最大共同节点，并在严格元素/键型 MCS 给出更大完整结果时使用后者。MCS 与 R-group 分解各设置 3 秒限制；超时或无法分解不生成虚构位点。低于 60% 的覆盖仅提示局部对齐，不自动认定骨架跃迁。
- R 标签只在本次对齐中有效，可能存在对称歧义，不等于专利 R 编号。多连接点片段会标记为桥连，不能分别认作多个单点替换。不同日期家族的片段差异只描述已整理样本，不据此判定探索终止或优化因果；未完整分析立体变化及杂原子替换。
- 单次最多 16 份专利、36 张证据卡；排除多组分和超过 100 重原子的结构。索引结构不参与程序骨架信号和 R 分解，未整理实施例的家族可能保持未归组。当前六张专利卡仍待独立化学家复核；这不是全库自动程序重建或科学验收完成。

实现位于 `phase0/sar/programs.py`、`phase0/sar/scaffolds.py` 与 `phase0/web/programs.js`。使用 [RDKit scaffold network](https://www.rdkit.org/docs/source/rdkit.Chem.Scaffolds.rdScaffoldNetwork.html) 和 [R-group decomposition](https://www.rdkit.org/docs/source/rdkit.Chem.rdRGroupDecomposition.html)。
