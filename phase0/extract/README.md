# 分级抽取控制（迭代 I3）

抽取的**控制逻辑**：页面分区、分级调用、身份核对、冲突处理、交叉校验、置信度与输出。它不读 PDF、不调用模型；真正的抽取器（结构化来源、全文解析、结构图识别、表格识别）以函数形式注入，可随时替换或做横向对比。

## 流程

1. **页面分区**（`partition.py`）：按页面文字把专利分为活性表、实施例、中间体区域，合并成页码范围，并保留判定依据。偶然提到 IC50 的正文页不会被当成活性表；中间体区域单独标出，避免与实施例混淆。
2. **分级调用**（`cascade.py`）：各级依次运行，例如 L1 结构化记录 → L2 全文 → L3 PDF 图表识别。第一级报告全部发现；之后只把仍缺的必填字段交给下一级；必填字段齐全后，后面更昂贵的级别不再调用。
3. **身份核对**：每条抽取结果必须带上来源页面上实际显示的公开号和实施例编号；对不上就拒绝并说明原因，不会改挂到别的实施例上。字段取值也会校验（角色、状态、限定符、有限数值）。
4. **冲突**：后一级与前一级不一致时，两个值都保留并标为冲突、降低置信度，不静默取其一。
5. **交叉校验**：报告的质谱值与结构比对（`mass_check`）；可选注入名称转结构（如 OPSIN）并比对 InChIKey。
6. **置信度**：
   - 化合物：有任何标记（冲突、质量不符、名称不符、结构无效、字段缺失）为 low；质量一致，且名称一致或两级独立给出同一结构时为 high；其余为 medium。
   - 观测：有冲突或缺失为 low；所有字段都由两级以上独立给出为 high；其余为 medium（单一来源）。
7. **输出**（`outputs.py`）：
   - 金标准格式的预测，可直接交给 `phase0.eval.extraction_metrics` 评测；缺字段的观测不输出（计为漏抽，不算编造）；
   - 台账提交记录，全部 `proposed`，缺口中写明抽取置信度和标记；实验必须对应到台账中已有的实验定义，否则拒绝而不是凭表格猜协议；
   - 给复核人看的 Markdown 抽取报告：分区、各级调用、置信度分布、需要核对的条目（low 在前）、冲突与被拒绝的结果。

## 已知边界（测试中有专门用例）

- 两个来源给出**同一个错误**（例如一个抄自另一个）时，“两级一致”规则会给出 high，质谱校验也查不出同分异构。评测中这会计为未标记错误——这正是需要金标准和独立复核的原因。
- 置信度规则是初始设定，需要在 I0 金标准扩充后用评测结果校准。
