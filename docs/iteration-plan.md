# SAR Atlas 产品化迭代方案

> 依据：当前功能清单（[FEATURES.md](../FEATURES.md)）、六步工作流（[sar-workflow.md](sar-workflow.md)）、竞品格局分析（第 1.1 节），以及对 *The Virtual Biotech*（Zhang et al., bioRxiv 2026, doi:10.64898/2026.02.23.707551）多 agent 框架的借鉴（论文原文未能直接读取，借鉴内容来自摘要与第三方复现代码，相关设计需对照原文核实），以及墨灵格博客《AI Agent 驱动的专利药物数据挖掘——从专利原文到 SAR 分析》（2026-09-26，礼来 DACRA 专利案例，下称“DACRA 案例”）。
>
> 文中周期为估计值，按 1–2 名全职工程师 + 1 名兼职药物化学顾问测算。

## 0. 产品定位与不可妥协的原则

**定位**：**审计级竞品 SAR 证据层**，服务药化团队的竞品调研、立项和 BD 尽调。输入靶点、竞品公司、专利号或结构，输出可追溯到原文页码的结构—活性证据、替换先例和候选改造方向。

不与数据库拼数据量，不与生成式平台拼分子设计；做可被集成的一层：接入已有数据库和开源抽取工具作为来源，结果可导出给生成式设计工具作为约束。

**目标早期客户**：没有商业 SAR 数据库预算的中小 biotech、CRO 药化团队、做 BD 尽调的团队。以免费试点换取真实评测数据。

**北极星指标**：化学家完成一次“某靶点竞品 SAR 调研”所需时间，以及其中经复核确认的证据条数。

**原则**（贯穿全部迭代，写入代码与测试）：

1. **数字只由确定性代码产生**。LLM / agent 负责检索、抽取、起草和审查，不计算、不判定可比性。
2. **每个数值可回溯**：文档 → 页码 / 表格 / 坐标框 → 原始文本或图像，附快照哈希。
3. **agent 写入一律为“待确认”**；只有人工复核才能改为“已确认”。
4. **证据不足就弃答**；限定值、缺失值不参与计算，不补零、不插值。
5. **事实、假设、缺口分开展示**；不从日期顺序推断研发演化。

## 1. 现状基线

| 维度 | 现状 | 主要缺口 |
|---|---|---|
| 入口 | 专利号、SMILES、靶点三种检索 | 在线结果不进入台账 |
| 数据 | 2 份专利（6 个实施例）+ 2 篇论文，37 条结构、320 条观测 | 依赖手工转录，规模极小 |
| 分析 | A/B 对照、骨架 / R 基团、程序聚类、1–8 对批次汇总 | 无全库 MMP、SAR 矩阵、活性悬崖、统计噪声 |
| 审查 | 规则审查 + 本机人工复核记录 | 复核人身份不可验证，无 agent 审查 |
| 工程 | `http.server`、文件缓存、原生 JS、192+ 项测试、CI | 无数据库、账号、异步任务 |

### 1.1 竞品格局与差异化

竞品信息来自公开页面、论文和搜索摘要，多为厂商或作者自述，未逐一核实。

| 类别 | 代表 | 与本项目的关系 |
|---|---|---|
| 人工整理的 SAR / 专利数据库 | GOSTAR（Excelra，自称 1060 万活性分子）、Reaxys、CAS SciFinder / STN、智慧芽新药情报库与化学库、医药魔方 | 数据量远超本项目；既是替代品，也可作为数据源 |
| 开源抽取工具 | BioChemInsight（自报三类任务平均准确率 > 90%）、Doc2SAR、OpenChemIE、MolScribe、DECIMER | 覆盖 I3 大部分抽取能力；**直接集成，不重写** |
| 懂专利的药化 AI 助手 | PharmMaster（见 Bohrium + SciMaster 论文，arXiv 2512.20469） | **最直接的竞品**：专利解析、Markush 范围重建、跨专利 SAR 汇总、FTO 评估 |
| 生成式设计 + 自有管线 | 英矽智能 Chemistry42 / Science42、晶泰科技（多智能体 + 机器人自主实验） | 不同赛道；潜在客户或合作方 |
| 通用科研 agent | Virtual Biotech、智慧芽 Eureka | 覆盖面广，药化 SAR 较浅 |
| 通用 agent + 自定义 skill | 豆包、WorkBuddy 等 + DECIMER skill（见 DACRA 案例） | 门槛低、灵活、几乎零成本，熟练用户几小时即可完成单份专利抽取；**个人用户最可能的替代方案**。其局限：页码需人工写入提示词、数据未经核验、缺失统一填 ND、无可比性判断、不可重放 |

**计划完成后可能成立的差异点**（均需评测证明）：

1. **审计级可追溯**：每个数值追到文档、页码、坐标框、原文和快照哈希；agent 写入先为“待确认”；证据不足时弃答。对外核心指标是“**未标记错误数**”，而不只是整体准确率。
2. **测量可比性由系统把关**：限定值、缺失值、跨 assay 数据不计算倍数，正反例都保留。对外核心指标是“**可比性误判数**”。
3. **竞品程序视角**：按专利家族、优先权日、候选研发程序组织证据，事实、假设、缺口分开。
4. **可私有化、透明、低成本**：可自托管，规则与代码公开，结构数据默认不外发。
5. **新专利跟进快**：并行抽取 + 监控 agent，目标是新公开专利几天内完成抽取并进入复核（需实测）。

**对“通用 agent + skill”的回应**：本项目的价值不是“能抽取”，而是抽取之后的可审计、可比性判断、团队复核和规模化。DACRA 案例的附件明确标注“未经人工核验”，其 3D-QSAR 却直接建在这批数据上，正是本项目要解决的问题。

**明显劣势**：数据规模无法与商业数据库相比；抽取能力尚未实测、没有技术领先；暂无 Markush 与 FTO；没有生成设计和湿实验闭环；严格弃答可能被认为“慢”；缺少客户背书。

## 2. 目标架构

```
入口：专利号 / 靶点 / 竞品公司 / SMILES / 上传 PDF、SDF
   │
   ▼
编排者（Research Lead）── 简报（Briefing）── 澄清访谈
   │ 分派
   ▼
专业 agent：检索员 · 专利抽取员 · 文献抽取员 · 结构核对员
   │ 仅通过 MCP 工具访问数据；写入状态均为“待确认”
   ▼
证据台账（唯一数据源）
   Document · Compound · Assay · Observation · Location · Relation · Review · Trace
   │
   ▼
确定性分析服务：可比性 · MMP · R 基团矩阵 · 骨架网络 · 程序聚类 · 时间线
   │
   ▼
审查 agent（结构化裁决）→ 人工复核 → 报告 / 问答 / 导出
```

### 2.1 Agent 组织（借鉴 Virtual Biotech，按本领域裁剪）

| 角色 | 职责 | 工具 | 模型档位 | 输出 |
|---|---|---|---|---|
| 编排者 Research Lead | 澄清需求、拆解任务、分派、汇总；**自身不查数据、不做分析** | 调用其他 agent | 强 | 任务计划、最终报告草稿（仅引用证据 ID） |
| 简报员 Briefing | 调研前给出数据概况：专利家族数、论文数、有活性表的比例 | patents、chembl（只读计数） | 快 | 可行性简报 |
| 检索员 Scout | 从靶点 / 公司扩展到专利家族、引用和论文；生成候选程序 | patents、chembl、surechembl | 强 | 文档清单 + 检索日志 + 覆盖缺口 |
| 专利抽取员 | 单份专利分级抽取实施例、结构和活性 | patents、pdf、ocsr、ledger.propose | 强 | 待确认证据记录 |
| 文献抽取员 | 论文图表与 ChEMBL 记录核对、补原文定位 | chembl、pdf、ledger.propose | 强 | 待确认证据记录 |
| 结构核对员 | 结构图识别结果与名称、分子式、质谱交叉验证 | chem、opsin | 快 | 置信度与冲突说明 |
| 审查员 Reviewer | 审查抽取与结论：跨实验比较、因果越界、限定值误用、覆盖不足 | ledger（只读）、analysis | 强 | APPROVE / 有条件通过 / 退回；must-fix 与 should-fix 清单 |
| 监控员 Monitor | 定期发现新公开专利和论文，与台账比对 | patents、chembl | 快 | 变化提醒（不写入已确认数据） |

与论文的差异：论文由 CSO 用文字综合结论；本项目中编排者的报告只能引用台账证据 ID，数字由分析服务填入，并经过 `narrate.py` 式的引用审计。

## 3. 迭代计划

### I0 基线与评测集（2 周）

**目标**：先定义“好”，再动手扩展。

- 访谈 3–5 位药物化学家，确认最高频的 3 个任务，并写成验收用例。
- 标注金标准集：ALK 靶点 5 份专利（含现有 2 份），逐字段标注实施例编号、结构、活性值、限定符、单位、assay、页码。
- **第二靶点**：加入礼来 DACRA 3 份专利（WO2025240893、WO2026193091、WO2026193092）。它们是激动剂（EC50 + Emax），含分级活性数据和两种测试格式，用于检验下文 I1 / I3 的新能力。DACRA 案例公开的数据集作为一条横向对比基线；因其未经核验，只作对照、抽样人工核对，不当标准答案。
- 定义抽取指标：结构精确匹配率（InChIKey）、数值 + 限定符 + 单位完全正确率、编号对应正确率、页码定位正确率、**未标记的错误值数**。
- 固化现有测试为回归基线。
- **横向对比基线**：在同一批金标准专利上跑 BioChemInsight、Doc2SAR 等开源工具，并与 ChEMBL 记录对照；能取得试用权限时加入 GOSTAR。除常规准确率外，重点统计“未标记错误数”和“可比性误判数”。

**验收**：金标准集入库，评测脚本可一键输出各项指标；横向对比报告完成；用户任务清单获顾问确认。

**进度**（2026-09-27）：

- [x] 金标准 v0：由现有 2 份专利证据包派生，待独立复核
- [ ] ALK 另 3 份专利、DACRA 3 份专利的人工标注
- [x] （提前完成 I1 部分）类型化台账数据结构与无损迁移：320 条观测往返哈希一致（`phase0/ledger/`）

### I1 证据台账底座（3–4 周）

**目标**：所有入口写入同一台账，所有分析只读台账。

- 用 pydantic 定义实体：`Document / Compound / Assay / Observation / Location / Relation / Review / Trace`；每个字段带 `source` 与 `status`（proposed / confirmed / rejected）。
- 存储接口抽象；先用 SQLite + RDKit，I7 切换到 PostgreSQL + RDKit cartridge。
- 字段扩展（依据 DACRA 案例暴露的数据形态）：
  - **化合物角色**：实施例 / 中间体 / 参比化合物 / 试剂，必填；
  - **分级活性值**：保存等级及其区间定义，不当连续数值参与回归或倍数计算；
  - **Emax 等激动剂终点**，以及**协议变体**（如 10 点与 20 点格式）；
  - **缺失语义细分**：未测、原文空白、未报告、不适用分开记录，不统一成 ND。
- `Relation` 类型细分：同族、姊妹申请（同日提交、申请号连续、优先权独立）、引用、发明人重叠；每条附判定依据，不从日期推断演化。
- 迁移：`patent_evidence/*.json`、`curated/*` 导入台账；`lineage.py` 中写死的 `EARLY/LATE` 改为 `Relation` 记录。
- 专利检索、SMILES / 靶点检索结果可“加入台账”（状态为 proposed）。
- **开放导入接口**：ChEMBL 批量导入；GOSTAR、智慧芽等商业库的用户自有导出文件（CSV / SDF）可作为来源导入，保留原库记录 ID 作为溯源。
- 现有分析模块（`evidence_pair`、`sar_workflow`、`scaffolds`、`programs`）改为读取台账。

**验收**：现有 320 条观测无损迁移（哈希比对）；全部测试通过；在线检索的记录可进入台账且标为待确认。

### I2 工具层与可追溯工作目录（2 周）

**目标**：为 agent 提供受控的数据访问接口。

- 按数据源拆分 MCP server（FastMCP）：`patents`、`chembl`、`surechembl`、`ledger`、`chem`（RDKit 分析）、`pdf`。
- 统一返回格式 `{summary, data, preview}`，控制上下文开销。
- `ledger` 只提供 `query` 与 `propose`，**不提供 confirm**。
- 每次运行生成工作目录：JSONL 记录每次工具调用、参数、结果哈希，与台账 `report_id` 关联。

**验收**：工具有单元测试且无需 API key；一次 agent 运行可从轨迹完整重放。

### I3 分级抽取（3–4 周）★ 核心

**目标**：用 agent 替代手工转录，同时保证可审计。

**策略：集成而非自研**。结构图识别、活性表抽取直接接入开源工具（BioChemInsight、Doc2SAR、MolScribe、DECIMER，按 I0 横向对比结果选型，并核查许可证）；本项目只做分级控制、交叉验证、置信度和复核，这是差异化所在。

- **文档分区（抽取前）**：自动识别活性表区、实施例区、中间体区的页码范围，只把相关页交给后续抽取，节省 token 并减少干扰。DACRA 案例由人工把页码写进提示词，本项目要自动完成，并把分区结果作为证据留存、可人工修正。
- 分级抽取的控制逻辑用确定性代码实现（参考论文的三级 cascade）：
  - **L1 结构化来源**：SureChEMBL / ChEMBL 文档记录；
  - **L2 专利全文**：现有 `patents.py`（Google Patents）的实施例定位；新增 WIPO PATENTSCOPE 的 ST.36 XML 作为第二来源，两者互相校验；
  - **L3 PDF**：调用集成的开源工具做结构图识别与活性表抽取。
  - 必填字段按记录类型定义（如活性行必须有 assay、终点、数值、限定符、单位）；缺失才升级到下一级。
  - **每一级都核对“公开号 + 实施例编号”**，逐字段记录来源级别与页码。
- 化合物角色判定：区分实施例与中间体、参比化合物，这是专利抽取的高频错误来源。
- 交叉验证：**第一道质控为 LCMS / MS 分子量与 RDKit 计算值比对**（成本低、效果好，异常高亮）；再加结构图识别的 SMILES ↔ 实施例 IUPAC 名称（OPSIN）↔ 分子式；按一致程度分为高 / 中 / 低置信度。分子量一致不代表结构正确（同分异构、立体化学），不能单独作为确认依据。
- 复核队列界面：原文截图与抽取结果并排，一键确认 / 修改 / 拒绝；修改记录回流为评测数据。
- **每份专利生成可读的抽取报告**：由 I2 的调用记录自动生成，列出分区结果、遇到的问题、低置信度项和冲突，化学家复核前先看报告，知道风险在哪里。

**验收**（初始目标，在 I0 金标准集上校准）：
- 数值 + 限定符 + 单位完全正确率 ≥ 98%；
- 高置信度结构的 InChIKey 精确匹配率 ≥ 95%；
- 未标记的错误值为 0（所有错误都应落在中 / 低置信度或冲突中）；
- 每份专利人工复核时间较手工转录缩短 ≥ 70%；
- 未标记错误数显著低于 I0 横向对比中的开源工具基线；
- DACRA 专利上：分级值、Emax、化合物角色均正确入库，缺失语义不被合并。

### I4 并行抽取与规模化（3 周）

**目标**：从“几个实施例”扩展到“一个靶点”。

- 并行抽取框架：一份专利一个 agent，并发上限可配置，按文档断点续跑，已完成的跳过；结果逐条 schema 校验。
- 成本与速率控制：单文档 token 预算、缓存原文与中间结果、失败重试上限。
- 实跑：ALK 竞品 50–100 份专利 + 相关论文，产出覆盖报告（已抽取 / 待复核 / 失败原因）。

**验收**：ALK 数据集可中断续跑；抽取指标不低于 I3；复核队列吞吐可满足 1 名化学家一周内完成确认。

### I5 分析升级（4 周）

**目标**：提供化学家日常使用的分析视图。

- 全台账 MMP（mmpdb），替代手选 8 对的限制；保留支持案例与反例。
- R 基团 SAR 矩阵：按系列和位点展开，热图展示活性；单位点用箱线图展示各基团的活性分布和出现频次。
- 候选扩展：Free-Wilson 分析，以及 AI 增强的 R 基团探索（Zhao et al., J. Chem. Inf. Model. 2025）。3D-QSAR 等建模不自研，导出给 Flare、Schrödinger 等工具。
- 分级活性值只做分组展示与等级比较，不参与数值回归。
- 统一换算 pIC50，引入实验噪声阈值（默认 0.3 log，可配置）；区分“有差异”与“在噪声内”。
- 活性悬崖检测；效率指标（LE、LLE / LipE、MW、cLogP、TPSA）随优先权日的轨迹。
- 子结构与相似性检索，去盐与互变异构处理。
- 证据等级：按独立文档数、assay 数、方向一致性、有无反例给出强 / 中 / 弱。

**验收**：各分析均为确定性计算并有测试；在洛拉替尼案例上由顾问核对 SAR 矩阵与 MMP 结论。

### I6 审查、编排与问答（4 周）

**目标**：从“工具集合”变成“能完成调研任务的系统”。

- 审查 agent：输出结构化裁决（APPROVE / 有条件通过 / 退回）和 must-fix / should-fix 清单；有 must-fix 时阻断汇总，打回相应 agent 修改。
- 编排者：调研前先出简报并做澄清访谈（靶点 / 突变体、终点、时间窗、竞品公司），再分派任务。
- 自然语言 SAR 问答：问题 → 台账查询 + MMP 工具 → 带证据 ID 的回答；沿用引用审计，证据不足时弃答。

**验收**：
- 审查 agent 在“植入错误集”（人为加入跨实验比较、限定值误算、因果越界等）上的检出率 ≥ 90%；
- 问答中每个数字都能解析到台账证据 ID；无法解析的回答被拦截；
- 端到端完成一次 ALK 竞品调研，顾问评价报告可用。

### 决策点 D1：Markush 与 FTO（M2 之后）

PharmMaster 等竞品已提供 Markush 范围重建和 FTO 评估。M2 完成后，根据试点客户反馈二选一，并在文档中记录理由：

- **做**：在 I5 之后插入迭代，先支持“输入结构是否落入某专利 Markush 范围”的判定，结果同样标注证据与置信度，不输出法律结论；
- **不做**：明确定位为 SAR 证据层，Markush / FTO 交给专业专利工具，提供导出接口对接。

### I7 产品化（持续）

- 后端 FastAPI + 异步任务队列；PostgreSQL + RDKit cartridge；原文按哈希存对象存储。
- 前端：项目空间（项目 → 文献集 → 台账 → 分析 → 复核 → 报告），Ketcher 结构编辑器，中英双语。
- 账号、权限与不可篡改审计日志；复核人身份真实可查。
- 导出 SDF / Excel / PPT；SDF 字段必须带证据 ID 与确认状态，让下游建模也能区分已确认与待确认数据；**导出给生成式设计工具**（如英矽智能、晶泰科技平台）作为约束或起点；监控 agent 定期推送竞品变化。
- 私有化部署：结构数据默认不出域；模型可经私有云端点调用。

## 5. 评测体系

| 层面 | 指标 | 数据 |
|---|---|---|
| 抽取 | 各字段正确率、未标记错误数、置信度校准；与开源工具的横向对比 | I0 金标准集，随复核修改持续扩充 |
| 分析 | 确定性结果与人工核对一致；可比性误判数 | 洛拉替尼、奥希替尼案例 + 顾问核对 |
| 审查 | 植入错误检出率、误报率 | 人为构造的错误集 |
| 问答 | 引用可解析率、弃答是否恰当 | 顾问编写的问题集 |
| 用户 | 单次调研耗时、每份专利复核时间、确认证据条数 | 试用记录 |

改提示词、换模型或调整阈值前后都要跑一遍评测；规则或阈值依据留出集调整时，需更换留出集。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 结构图识别错误（立体、Markush、R 基团标签） | 多路交叉验证；低置信度强制人工；Markush 暂不自动展开 |
| agent 编造数值 | 数值只能来自抽取原文片段并附坐标；审查 agent + 引用审计；写入仅为待确认 |
| 跨专利、跨实验误比较 | 可比性由确定性规则判定；跨来源只并列不计算 |
| 专利数据源访问受限或变化 | 多来源冗余；快照哈希变化即停用旧映射 |
| 成本失控 | 单文档预算；快模型做初筛；缓存 |
| 药企数据保密 | 默认本地解析；私有化部署；外发需显式开关 |
| 复核负担过重 | 按置信度排序复核；高置信度抽检；批量确认 |
| 竞品已覆盖核心能力（PharmMaster、开源抽取工具） | 以审计与可比性指标做横向对比证明差异；集成而非重复建设；D1 明确 Markush / FTO 取舍 |
| 集成的开源工具许可证或维护风险 | 选型时核查许可证；抽取层接口化，可替换工具 |
| 通用 agent + skill 以近零成本替代基础抽取 | 不以“能抽取”为卖点；以审计、可比性、团队复核和规模化证明价值；在 DACRA 数据上做公开对比 |
| 严格弃答被视为“不好用” | 同时展示“可给出的有限结论 + 缺口”，而不是只显示弃答；以试点反馈调整展示方式 |

## 7. 近两周可执行任务（I0 启动）

1. 与 2–3 位药物化学家各做一次 45 分钟访谈，整理 3 个核心任务。
2. 选定 ALK 金标准 5 份专利（WO2011138751A2、WO2013132376A1 + 3 份竞品），制定标注规范。
3. 编写 `eval/extraction_metrics.py` 与金标准数据格式，先用现有 6 个实施例跑通。
4. 起草台账 pydantic schema，评审后进入 I1。
5. 部署 BioChemInsight、Doc2SAR、MolScribe、DECIMER、OPSIN，核查许可证，在金标准集上完成首轮横向对比。
6. 联系 2–3 家潜在试点客户（中小 biotech / CRO 药化团队），确认试点靶点。
7. 阅读 PharmMaster 原论文，整理其能力边界，更新第 1.1 节。
8. 手动下载 DACRA 案例公开的 3 份专利数据集（百度网盘，当前环境无法直接访问）放入仓库评测目录，并获取 3 份专利原文。
