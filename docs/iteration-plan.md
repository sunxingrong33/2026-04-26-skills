# SAR Atlas 产品化迭代方案

> 依据：当前功能清单（[FEATURES.md](../FEATURES.md)）、六步工作流（[sar-workflow.md](sar-workflow.md)），以及对 *The Virtual Biotech*（Zhang et al., bioRxiv 2026, doi:10.64898/2026.02.23.707551）多 agent 框架的借鉴。论文原文未能直接读取，借鉴内容来自摘要与第三方复现代码，相关设计需对照原文核实。
>
> 文中周期为估计值，按 1–2 名全职工程师 + 1 名兼职药物化学顾问测算。

## 0. 产品定位与不可妥协的原则

**定位**：面向药物化学家的竞品 SAR 证据平台。输入靶点、竞品公司、专利号或结构，输出可追溯到原文页码的结构—活性证据、替换先例和候选改造方向。

**北极星指标**：化学家完成一次“某靶点竞品 SAR 调研”所需时间，以及其中经复核确认的证据条数。

**原则**（贯穿全部迭代，写入代码与测试）：

1. **数字只由确定性代码产生**。LLM / agent 负责检索、抽取、起草和审查，不计算、不判定可比性。
2. **每个数值可回溯**：文档 → 页码 / 表格 / 坐标框 → 原始文本或图像，附快照哈希。
3. **agent 写入一律为“待确认”**；只有人工复核才能改为“已确认”。
4. **证据不足就弃答**；限定值、缺失值不参与计算，不补零、不插值。
5. **事实、假设、缺口分开展示**；不从日期顺序推断研发演化。

## 1. 现状基线

| 维度 | 现状 | 主要缺口 |
|---|---|---|
| 入口 | 专利号、SMILES、靶点三种检索 | 在线结果不进入台账 |
| 数据 | 2 份专利（6 个实施例）+ 2 篇论文，37 条结构、320 条观测 | 依赖手工转录，规模极小 |
| 分析 | A/B 对照、骨架 / R 基团、程序聚类、1–8 对批次汇总 | 无全库 MMP、SAR 矩阵、活性悬崖、统计噪声 |
| 审查 | 规则审查 + 本机人工复核记录 | 复核人身份不可验证，无 agent 审查 |
| 工程 | `http.server`、文件缓存、原生 JS、192+ 项测试、CI | 无数据库、账号、异步任务 |

## 2. 目标架构

```
入口：专利号 / 靶点 / 竞品公司 / SMILES / 上传 PDF、SDF
   │
   ▼
编排者（Research Lead）── 简报（Briefing）── 澄清访谈
   │ 分派
   ▼
专业 agent：检索员 · 专利抽取员 · 文献抽取员 · 结构核对员
   │ 仅通过 MCP 工具访问数据；写入状态均为“待确认”
   ▼
证据台账（唯一数据源）
   Document · Compound · Assay · Observation · Location · Relation · Review · Trace
   │
   ▼
确定性分析服务：可比性 · MMP · R 基团矩阵 · 骨架网络 · 程序聚类 · 时间线
   │
   ▼
审查 agent（结构化裁决）→ 人工复核 → 报告 / 问答 / 导出
```

### 2.1 Agent 组织（借鉴 Virtual Biotech，按本领域裁剪）

| 角色 | 职责 | 工具 | 模型档位 | 输出 |
|---|---|---|---|---|
| 编排者 Research Lead | 澄清需求、拆解任务、分派、汇总；**自身不查数据、不做分析** | 调用其他 agent | 强 | 任务计划、最终报告草稿（仅引用证据 ID） |
| 简报员 Briefing | 调研前给出数据概况：专利家族数、论文数、有活性表的比例 | patents、chembl（只读计数） | 快 | 可行性简报 |
| 检索员 Scout | 从靶点 / 公司扩展到专利家族、引用和论文；生成候选程序 | patents、chembl、surechembl | 强 | 文档清单 + 检索日志 + 覆盖缺口 |
| 专利抽取员 | 单份专利分级抽取实施例、结构和活性 | patents、pdf、ocsr、ledger.propose | 强 | 待确认证据记录 |
| 文献抽取员 | 论文图表与 ChEMBL 记录核对、补原文定位 | chembl、pdf、ledger.propose | 强 | 待确认证据记录 |
| 结构核对员 | 结构图识别结果与名称、分子式、质谱交叉验证 | chem、opsin | 快 | 置信度与冲突说明 |
| 审查员 Reviewer | 审查抽取与结论：跨实验比较、因果越界、限定值误用、覆盖不足 | ledger（只读）、analysis | 强 | APPROVE / 有条件通过 / 退回；must-fix 与 should-fix 清单 |
| 监控员 Monitor | 定期发现新公开专利和论文，与台账比对 | patents、chembl | 快 | 变化提醒（不写入已确认数据） |

与论文的差异：论文由 CSO 用文字综合结论；本项目中编排者的报告只能引用台账证据 ID，数字由分析服务填入，并经过 `narrate.py` 式的引用审计。

## 3. 迭代计划

### I0 基线与评测集（2 周）

**目标**：先定义“好”，再动手扩展。

- 访谈 3–5 位药物化学家，确认最高频的 3 个任务，并写成验收用例。
- 标注金标准集：ALK 靶点 5 份专利（含现有 2 份），逐字段标注实施例编号、结构、活性值、限定符、单位、assay、页码。
- 定义抽取指标：结构精确匹配率（InChIKey）、数值 + 限定符 + 单位完全正确率、编号对应正确率、页码定位正确率、**未标记的错误值数**。
- 固化现有测试为回归基线。

**验收**：金标准集入库，评测脚本可一键输出各项指标；用户任务清单获顾问确认。

### I1 证据台账底座（3–4 周）

**目标**：所有入口写入同一台账，所有分析只读台账。

- 用 pydantic 定义实体：`Document / Compound / Assay / Observation / Location / Relation / Review / Trace`；每个字段带 `source` 与 `status`（proposed / confirmed / rejected）。
- 存储接口抽象；先用 SQLite + RDKit，I7 切换到 PostgreSQL + RDKit cartridge。
- 迁移：`patent_evidence/*.json`、`curated/*` 导入台账；`lineage.py` 中写死的 `EARLY/LATE` 改为 `Relation` 记录。
- 专利检索、SMILES / 靶点检索结果可“加入台账”（状态为 proposed）。
- 现有分析模块（`evidence_pair`、`sar_workflow`、`scaffolds`、`programs`）改为读取台账。

**验收**：现有 320 条观测无损迁移（哈希比对）；全部测试通过；在线检索的记录可进入台账且标为待确认。

### I2 工具层与可追溯工作目录（2 周）

**目标**：为 agent 提供受控的数据访问接口。

- 按数据源拆分 MCP server（FastMCP）：`patents`、`chembl`、`surechembl`、`ledger`、`chem`（RDKit 分析）、`pdf`。
- 统一返回格式 `{summary, data, preview}`，控制上下文开销。
- `ledger` 只提供 `query` 与 `propose`，**不提供 confirm**。
- 每次运行生成工作目录：JSONL 记录每次工具调用、参数、结果哈希，与台账 `report_id` 关联。

**验收**：工具有单元测试且无需 API key；一次 agent 运行可从轨迹完整重放。

### I3 分级抽取（4–6 周）★ 核心

**目标**：用 agent 替代手工转录，同时保证可审计。

- 分级抽取的控制逻辑用确定性代码实现（参考论文的三级 cascade）：
  - **L1 结构化来源**：SureChEMBL / ChEMBL 文档记录；
  - **L2 专利 HTML 全文**：现有 `patents.py` 的实施例定位；
  - **L3 PDF**：结构图识别（MolScribe / DECIMER）+ 活性表抽取。
  - 必填字段按记录类型定义（如活性行必须有 assay、终点、数值、限定符、单位）；缺失才升级到下一级。
  - **每一级都核对“公开号 + 实施例编号”**，逐字段记录来源级别与页码。
- 交叉验证：结构图识别的 SMILES ↔ 实施例 IUPAC 名称（OPSIN）↔ 分子式 / 质谱 m/z；按一致程度分为高 / 中 / 低置信度。
- 复核队列界面：原文截图与抽取结果并排，一键确认 / 修改 / 拒绝；修改记录回流为评测数据。

**验收**（初始目标，在 I0 金标准集上校准）：
- 数值 + 限定符 + 单位完全正确率 ≥ 98%；
- 高置信度结构的 InChIKey 精确匹配率 ≥ 95%；
- 未标记的错误值为 0（所有错误都应落在中 / 低置信度或冲突中）；
- 每份专利人工复核时间较手工转录缩短 ≥ 70%。

### I4 并行抽取与规模化（3 周）

**目标**：从“几个实施例”扩展到“一个靶点”。

- 并行抽取框架：一份专利一个 agent，并发上限可配置，按文档断点续跑，已完成的跳过；结果逐条 schema 校验。
- 成本与速率控制：单文档 token 预算、缓存原文与中间结果、失败重试上限。
- 实跑：ALK 竞品 50–100 份专利 + 相关论文，产出覆盖报告（已抽取 / 待复核 / 失败原因）。

**验收**：ALK 数据集可中断续跑；抽取指标不低于 I3；复核队列吞吐可满足 1 名化学家一周内完成确认。

### I5 分析升级（4 周）

**目标**：提供化学家日常使用的分析视图。

- 全台账 MMP（mmpdb），替代手选 8 对的限制；保留支持案例与反例。
- R 基团 SAR 矩阵：按系列和位点展开，热图展示活性。
- 统一换算 pIC50，引入实验噪声阈值（默认 0.3 log，可配置）；区分“有差异”与“在噪声内”。
- 活性悬崖检测；效率指标（LE、LLE / LipE、MW、cLogP、TPSA）随优先权日的轨迹。
- 子结构与相似性检索，去盐与互变异构处理。
- 证据等级：按独立文档数、assay 数、方向一致性、有无反例给出强 / 中 / 弱。

**验收**：各分析均为确定性计算并有测试；在洛拉替尼案例上由顾问核对 SAR 矩阵与 MMP 结论。

### I6 审查、编排与问答（4 周）

**目标**：从“工具集合”变成“能完成调研任务的系统”。

- 审查 agent：输出结构化裁决（APPROVE / 有条件通过 / 退回）和 must-fix / should-fix 清单；有 must-fix 时阻断汇总，打回相应 agent 修改。
- 编排者：调研前先出简报并做澄清访谈（靶点 / 突变体、终点、时间窗、竞品公司），再分派任务。
- 自然语言 SAR 问答：问题 → 台账查询 + MMP 工具 → 带证据 ID 的回答；沿用引用审计，证据不足时弃答。

**验收**：
- 审查 agent 在“植入错误集”（人为加入跨实验比较、限定值误算、因果越界等）上的检出率 ≥ 90%；
- 问答中每个数字都能解析到台账证据 ID；无法解析的回答被拦截；
- 端到端完成一次 ALK 竞品调研，顾问评价报告可用。

### I7 产品化（持续）

- 后端 FastAPI + 异步任务队列；PostgreSQL + RDKit cartridge；原文按哈希存对象存储。
- 前端：项目空间（项目 → 文献集 → 台账 → 分析 → 复核 → 报告），Ketcher 结构编辑器，中英双语。
- 账号、权限与不可篡改审计日志；复核人身份真实可查。
- 导出 SDF / Excel / PPT；监控 agent 定期推送竞品变化。
- 私有化部署：结构数据默认不出域；模型可经私有云端点调用。

## 5. 评测体系

| 层面 | 指标 | 数据 |
|---|---|---|
| 抽取 | 各字段正确率、未标记错误数、置信度校准 | I0 金标准集，随复核修改持续扩充 |
| 分析 | 确定性结果与人工核对一致 | 洛拉替尼、奥希替尼案例 + 顾问核对 |
| 审查 | 植入错误检出率、误报率 | 人为构造的错误集 |
| 问答 | 引用可解析率、弃答是否恰当 | 顾问编写的问题集 |
| 用户 | 单次调研耗时、每份专利复核时间、确认证据条数 | 试用记录 |

改提示词、换模型或调整阈值前后都要跑一遍评测；规则或阈值依据留出集调整时，需更换留出集。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 结构图识别错误（立体、Markush、R 基团标签） | 多路交叉验证；低置信度强制人工；Markush 暂不自动展开 |
| agent 编造数值 | 数值只能来自抽取原文片段并附坐标；审查 agent + 引用审计；写入仅为待确认 |
| 跨专利、跨实验误比较 | 可比性由确定性规则判定；跨来源只并列不计算 |
| 专利数据源访问受限或变化 | 多来源冗余；快照哈希变化即停用旧映射 |
| 成本失控 | 单文档预算；快模型做初筛；缓存 |
| 药企数据保密 | 默认本地解析；私有化部署；外发需显式开关 |
| 复核负担过重 | 按置信度排序复核；高置信度抽检；批量确认 |

## 7. 近两周可执行任务（I0 启动）

1. 与 2–3 位药物化学家各做一次 45 分钟访谈，整理 3 个核心任务。
2. 选定 ALK 金标准 5 份专利（WO2011138751A2、WO2013132376A1 + 3 份竞品），制定标注规范。
3. 编写 `eval/extraction_metrics.py` 与金标准数据格式，先用现有 6 个实施例跑通。
4. 起草台账 pydantic schema，评审后进入 I1。
5. 调研 MolScribe / DECIMER / OPSIN 的许可证、部署方式与在金标准集上的初测表现。
