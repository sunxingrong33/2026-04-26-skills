## 0. 本版变更摘要

1. **进度对账**：v1 的 I0–I3 中，所有不依赖外部数据的部分已完成（见第 1 节），I2 已整体完成。
2. **I3 拆为三段**：I3a PDF 接入与分区校准、I3b 抽取器集成与首次真实评测、I3c 复核队列界面。拆分原因：控制逻辑已就绪，剩下的每一段都卡在不同的外部输入上（PDF、标注、化学家时间），分开才能各自推进。
3. **新增 R1 收尾与加固**（无外部依赖，立即可做）：把浏览器测试纳入仓库，并提供一个在可联网机器上验证在线路径的脚本。
4. **新增 I2.5 真实模型 agent 首跑**，从 v1 的 I6 前移。工具层已就绪，尽早用真实模型检验 agent 是否遵守工具边界，可以降低后续迭代的风险；它只依赖 API key，可与 I3a 并行。
5. **置信度校准列入 I3b 验收**：当前规则是初始设定，而且已知存在“两个来源给出同一错误时评为高置信度”的盲区。
6. **评测体系新增四项指标**：页面分区准确率、高置信度的精确率、agent 越界行为数、重放一致率。
7. **新增第 3 节“阻塞项与依赖”**：列明每一项外部输入由谁提供、影响哪个迭代。

## 2. 实现中的经验（转为规则）

实现过程中，测试抓到了以下问题。它们对应的做法，从本版起作为工程规则执行。

| 问题 | 发生在 | 规则 |
|---|---|---|
| MCP SDK 默认静默丢弃未知参数，拼错的筛选条件会变成不带筛选的查询 | I2 | **外部 SDK 的默认行为若影响正确性，必须写测试守护**，并锁定版本 |
| pydantic 把整数质谱值 `357` 转成 `357.0`，校验容差被悄悄放宽 | I2 | 精度有意义的数值按原文字符串传递；类型声明把整数放在浮点之前 |
| 重放不一致：结果中带有“是否命中缓存”这类传输细节 | I2 | 工具结果只含证据本身；传输细节不进入结果哈希 |
| 必填字段逐步索取，导致一级抽取没问全、多调用一级 | I3 | 控制逻辑一次索取可能需要的全部字段；完整性按实际取得的值判断 |
| 新增统计键覆盖了同名旧键；`Assay` 漏掉复核状态 | I1 | 新字段先检索同名；**每类记录都必须有复核状态**，由数据模型强制 |
| 手写的“同分异构体”其实是同一个分子（吡唑环对称） | I3 测试 | **测试里的化学事实由 RDKit 断言**（分子式相同、InChIKey 不同），不靠手写判断 |
| 演示脚本假设提交后仍能算比值，实际系统正确地因重复测量阻断 | 演示 | 演示脚本也要有测试；系统的拒绝行为本身就是演示内容 |

另外两条贯穿始终的做法：**改造前保存输出快照，改完逐项比对**（跨专利关系、台账切换都这样做）；**已知盲区写成测试**，而不是只写在文档里。

## 4. 迭代计划（v1.2）

### R1 收尾与加固（约 1 周，无外部依赖，立即开始）

- 把浏览器测试纳入仓库：Playwright 作为可选开发依赖；用专利夹具页面和模拟 ChEMBL 响应覆盖“加入台账”、跨专利关联的“未展示原因”、六步工作流主路径；没有浏览器时自动跳过。
- 提供在线路径验证脚本（在可联网机器上运行）：检索两份专利、查询一个靶点的一页测量、写入台账并重放，输出一份核对报告，结果补入 `docs/baseline.md`。
- 页面上显示证据卡的质谱校验结果（目前只在接口和下载的 JSON 中）。
- 文档：各模块 README 与 `FEATURES.md` 保持一致；新增 `.mcp.json` 示例文件（不默认启用）。

**验收**：浏览器测试在 CI 中可选运行；在线验证脚本在本机跑通一次并记录结果。

### I3a PDF 接入与分区校准（1–2 周，PDF 到位后）

- PDF 文字提取适配器：逐页文字、页面快照哈希；扫描件标记为需 OCR，不静默跳过。
- 在 5 份真实 PDF 上人工标注页面区域（活性表、实施例、中间体），作为分区的小型金标准。
- 按标注调整分区规则；分区结果可人工修正，修正记录保留。
- 分区接入分级抽取，抽取报告显示真实页码范围。

**验收**：分区在 5 份 PDF 上的页面级准确率有记录（目标：活性表页召回 ≥ 95%，不把中间体页判为实施例页）；修正记录可追溯。

### I3b 抽取器集成与首次真实评测（3–4 周，PDF 与标注到位后）★ 核心

- **L1**：ChEMBL / SureChEMBL 文档记录适配器（先核实 SureChEMBL 当前的访问方式与许可）。
- **L2**：专利全文实施例段落与 WIPO ST.36 XML 适配器，两者互相校验。
- **L3**：结构图识别（MolScribe、DECIMER 选型，先核查许可证）与活性表抽取；接入 OPSIN 做名称转结构交叉校验。
- 在金标准（ALK 5 份 + DACRA 3 份）上做**第一次真实评测**；与 BioChemInsight / Doc2SAR、DACRA 公开数据集横向对比（后者未经核验，只作对照）。
- **置信度校准**：统计各置信度等级的实际正确率；调整规则，使高置信度的精确率达到目标；已知盲区（同源错误）评估实际发生频率。
- 协议段落抽取：为新实验建立定义，不从活性表猜协议。

**验收**（v1 目标沿用，在真实数据上校准后可调整，调整需记录理由）：
- 数值 + 限定符 + 单位完全正确率 ≥ 98%；高置信度结构 InChIKey 精确匹配 ≥ 95%；
- 未标记错误数为 0，或逐条列出并说明原因；
- 未标记错误数显著低于开源工具基线；
- DACRA 专利上分级值、Emax、化合物角色正确入库，缺失语义不被合并。

### I3c 复核队列界面（约 2 周，可与 I3b 后半段并行）

- 原文截图（按页码与坐标）与抽取字段并排；一键确认 / 修改 / 拒绝，调用现有 `LedgerStore.review`。
- 按置信度排序（低置信度在前）；高置信度支持抽检与批量确认。
- 修改记录回流为评测数据。
- 本机最小账号：复核人身份可区分（完整账号体系仍在 I7）。

**验收**：一名化学家完成 1 份专利的复核，记录耗时，并与手工转录对比（v1 目标：缩短 ≥ 70%）。

### I2.5 真实模型 agent 首跑（1–2 周，API key 到位后，可与 I3a 并行）

- 用现有 MCP 工具，让真实模型完成 3–5 个小任务。例如：比较两个实施例的证据并说明能否比较；从给定的一页测量中提交缺失记录；解释某条关联为什么没有展示。
- 评测 agent 行为：回答中的数字是否都来自工具结果（沿用引用审计）；有没有尝试确认记录或绕过工具；是否正确对待限定值和缺失值；越界行为计数。
- 每次运行保存记录并重放；统计 token 与成本。

**验收**：越界行为数与引用可解析率有记录；所有运行可重放；据此修订工具描述，并写入 I6 的设计。

### I4 并行抽取与规模化（约 3 周，I3b 达标后）

- 在现有运行记录机制上构建并行抽取：一份专利一次运行，按文档断点续跑，已完成的跳过；并发与单文档预算可配置。
- 实跑 ALK 竞品 50–100 份专利，产出覆盖报告（已抽取 / 待复核 / 失败原因）。

**验收**：可中断续跑；抽取指标不低于 I3b；复核队列吞吐满足 1 名化学家一周内完成确认。

### I5 分析升级（约 4 周）

沿用 v1 I5 内容：全台账 MMP、R 基团 SAR 矩阵、pIC50 与噪声阈值、活性悬崖、效率指标轨迹、子结构与相似性检索、证据等级。分级活性值只做分组展示，不参与数值回归。新增一条：**分析工具同步加入 MCP 工具层**，agent 与页面使用同一套确定性计算。

### I6 审查、编排与问答（约 4 周）

沿用 v1 I6 内容，建立在已有工具层和 I2.5 的行为评测之上：审查 agent（结构化裁决、打回重做）、编排者（简报与澄清访谈）、自然语言 SAR 问答（引用审计、证据不足时弃答）。验收沿用 v1：植入错误检出率 ≥ 90%，回答中的数字都能解析到台账证据编号。

### 决策点 D1 与 I7

D1（Markush 与 FTO，做或不做）与 I7（产品化：FastAPI、PostgreSQL、项目空间、账号与审计、导出、私有化部署、监控）沿用 v1。I7 另加一项：**MCP SDK 的内部属性依赖**（未知参数拒绝）在升级 SDK 时重新评估；若 SDK 提供公开开关则改用公开方式。

## 7. 风险（v1.2 增补）

v1 第 6 节风险全部沿用，另增：

| 风险 | 对策 |
|---|---|
| 目前所有抽取验证都基于模拟抽取器，真实效果未知 | I3b 首次真实评测为最高优先级；结果如低于预期，如实记录并调整 I4 范围 |

| 页面分区规则只在示例文字上测试 | I3a 在真实 PDF 上校准，修正可人工覆盖 |

## 8. 近两周任务

**需要项目负责人**：

1. 把 5 份专利 PDF 放入仓库（建议 `phase0/data/pdf/`，大文件可用 Git LFS 或只放本地并记录哈希）。
2. 按 `phase0/data/gold/README.md` 开始标注 ALK 另 3 份专利中的至少 1 份，先跑通标注流程。
3. 在可联网的本机运行一次完整演示路径（专利检索、靶点测量、加入台账），记录问题。
4. 决定 I2.5 的模型 API key 与预算；约 1–2 位化学家访谈时间。

**可立即开始（开发）**：

1. R1：浏览器测试入仓、在线验证脚本、证据卡页面显示质谱校验。
2. I3a 预备：PDF 文字提取适配器（先用公开的非专利 PDF 样例开发，PDF 到位后切换）。
3. I3b 预备：核查 MolScribe、DECIMER、OPSIN、SureChEMBL 的许可证与部署方式，形成选型记录。
