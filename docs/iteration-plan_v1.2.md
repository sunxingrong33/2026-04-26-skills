## 0. 本版变更摘要

1. **进度对账**：v1 的 I0–I3 中，所有不依赖外部数据的部分已完成（见第 1 节），I2 已整体完成。
2. **I3 拆为三段**：I3a PDF 接入与分区校准、I3b 抽取器集成与首次真实评测、I3c 复核队列界面。拆分原因：控制逻辑已就绪，剩下的每一段都卡在不同的外部输入上（PDF、标注、化学家时间），分开才能各自推进。
3. **新增 R1 收尾与加固**（无外部依赖，立即可做）：把浏览器测试纳入仓库，并提供一个在可联网机器上验证在线路径的脚本。
4. **新增 I2.5 真实模型 agent 首跑**，从 v1 的 I6 前移。工具层已就绪，尽早用真实模型检验 agent 是否遵守工具边界，可以降低后续迭代的风险；它只依赖 API key，可与 I3a 并行。
5. **置信度校准列入 I3b 验收**：当前规则是初始设定，而且已知存在“两个来源给出同一错误时评为高置信度”的盲区。
6. **评测体系新增四项指标**：页面分区准确率、高置信度的精确率、agent 越界行为数、重放一致率。
7. **新增第 3 节“阻塞项与依赖”**：列明每一项外部输入由谁提供、影响哪个迭代。
8. **新增 I2.6 结构检索入口**（2026-09-28 补充）：按精确、相似性、子结构三种方式，用结构在外部来源中检索专利和文献。v1 只在 I5 规划了台账内部的子结构与相似性检索，没有“从一个结构出发找竞品专利和论文”这一入口；而这是药物化学家做竞品调研最常用的起点。本地检索的实现从 I5 提前到这里，两处共用。
9. **修订（R1 与 I2.6 开发完成后）**：第 1 节进度对账增加 R1、I2.6 两行；第 2 节新增五条工程规则（来自 I2.6 的实现）；第 3 节 SureChEMBL、PubChem 的核实状态更新，在线核对成为唯一卡住 M1.5 的外部条件；第 7 节增补外部来源相关风险；第 8 节任务重排。
10. **新增 I2.7 目标驱动的 SAR 调研闭环**（2026-09-28 补充）：对照药物化学家的完整流程——输入陌生结构和项目目标 → 找相关文献与系列 → 整理可比较的结构变化 → 按位点总结证据 → 输出下一轮实验讨论材料——现有功能只覆盖其中一部分：没有项目目标输入，分子对要手动挑、最多 8 对，没有噪声阈值和多性质并排，没有补测建议和覆盖缺口报告。全台账自动配对（MMP）与噪声阈值从 I5 提前到 I2.7，I5 复用。

## 2. 实现中的经验（转为规则）

实现过程中，测试抓到了以下问题。它们对应的做法，从本版起作为工程规则执行。

| 问题 | 发生在 | 规则 |
|---|---|---|
| MCP SDK 默认静默丢弃未知参数，拼错的筛选条件会变成不带筛选的查询 | I2 | **外部 SDK 的默认行为若影响正确性，必须写测试守护**，并锁定版本 |
| pydantic 把整数质谱值 `357` 转成 `357.0`，校验容差被悄悄放宽 | I2 | 精度有意义的数值按原文字符串传递；类型声明把整数放在浮点之前 |
| 重放不一致：结果中带有“是否命中缓存”这类传输细节 | I2 | 工具结果只含证据本身；传输细节不进入结果哈希 |
| 必填字段逐步索取，导致一级抽取没问全、多调用一级 | I3 | 控制逻辑一次索取可能需要的全部字段；完整性按实际取得的值判断 |
| 新增统计键覆盖了同名旧键；`Assay` 漏掉复核状态 | I1 | 新字段先检索同名；**每类记录都必须有复核状态**，由数据模型强制 |
| 手写的“同分异构体”其实是同一个分子（吡唑环对称） | I3 测试 | **测试里的化学事实由 RDKit 断言**（分子式相同、InChIKey 不同），不靠手写判断 |
| 演示脚本假设提交后仍能算比值，实际系统正确地因重复测量阻断 | 演示 | 演示脚本也要有测试；系统的拒绝行为本身就是演示内容 |
| 测试夹具里手写的洛拉替尼结构把氟画错了环位置（区域异构体，分子式与质谱都查不出），由精确结构检索发现 | I2.6 | **夹具中的已知化合物用 InChIKey 与台账中整理过的结构比对**，并写测试守护 |
| 网络错误信息每次不同，失败的调用在重放时对不上 | I2.6 | 传输类失败返回固定措辞；可变的传输细节不进入结果 |
| “查不到”若不缓存，断网重放时无法复现同一答案 | I2.6 | 来源明确答复“查不到”的结果照常缓存；服务繁忙、连接失败等错误不缓存 |
| SureChEMBL 与 PubChem 常把同一分子关联到同一专利，容易被当成两份证据 | I2.6 | **接入新来源前先判断它与已有来源是否同源**；同源来源并列显示，不合并、不当作独立佐证（与抽取中“相关来源的一致不提高置信度”同理） |
| 外部接口的关键行为不在官方说明里（异步任务、请求体包装、结果上限），且开发环境无法访问 | I2.6 | **接入外部来源前先核实许可、限速与接口行为，写成核实记录**；未实连的接口在文档和页面标明“待在线核对”，由核对脚本首次验证 |

另外两条贯穿始终的做法：**改造前保存输出快照，改完逐项比对**（跨专利关系、台账切换都这样做）；**已知盲区写成测试**，而不是只写在文档里。

## 4. 迭代计划（v1.2）

### R1 收尾与加固（约 1 周，无外部依赖，立即开始）

- 把浏览器测试纳入仓库：Playwright 作为可选开发依赖；用专利夹具页面和模拟 ChEMBL 响应覆盖“加入台账”、跨专利关联的“未展示原因”、六步工作流主路径；没有浏览器时自动跳过。
- 提供在线路径验证脚本（在可联网机器上运行）：检索两份专利、查询一个靶点的一页测量、写入台账并重放，输出一份核对报告，结果补入 `docs/baseline.md`。
- 页面上显示证据卡的质谱校验结果（目前只在接口和下载的 JSON 中）。
- 文档：各模块 README 与 `FEATURES.md` 保持一致；新增 `.mcp.json` 示例文件（不默认启用）。

**验收**：浏览器测试在 CI 中可选运行；在线验证脚本在本机跑通一次并记录结果。

**进度（2026-09-28）**：开发部分已完成——浏览器测试入仓（`test_browser.py`，4 项；CI 可选任务）；在线路径核对脚本（`phase0.tools.verify_online`，模拟网络测试 2 项）；证据卡显示质谱校验；`.mcp.json.example` 及一致性测试；文档同步。测试 356 项。**待完成**：在可联网本机运行核对脚本并把结果补入 `docs/baseline.md`（需项目负责人）。

### I3a PDF 接入与分区校准（1–2 周，PDF 到位后）

- PDF 文字提取适配器：逐页文字、页面快照哈希；扫描件标记为需 OCR，不静默跳过。
- 在 5 份真实 PDF 上人工标注页面区域（活性表、实施例、中间体），作为分区的小型金标准。
- 按标注调整分区规则；分区结果可人工修正，修正记录保留。
- 分区接入分级抽取，抽取报告显示真实页码范围。

**验收**：分区在 5 份 PDF 上的页面级准确率有记录（目标：活性表页召回 ≥ 95%，不把中间体页判为实施例页）；修正记录可追溯。

### I3b 抽取器集成与首次真实评测（3–4 周，PDF 与标注到位后）★ 核心

- **L1**：ChEMBL / SureChEMBL 文档记录适配器（SureChEMBL 访问方式与许可已在 I2.6 核实，复用 `phase0/sar/surechembl.py` 的请求、缓存与重放机制）。
- **L2**：专利全文实施例段落与 WIPO ST.36 XML 适配器，两者互相校验。
- **L3**：结构图识别（MolScribe、DECIMER 选型，先核查许可证）与活性表抽取；接入 OPSIN 做名称转结构交叉校验。
- 在金标准（ALK 5 份 + DACRA 3 份）上做**第一次真实评测**；与 BioChemInsight / Doc2SAR、DACRA 公开数据集横向对比（后者未经核验，只作对照）。
- **置信度校准**：统计各置信度等级的实际正确率；调整规则，使高置信度的精确率达到目标；已知盲区（同源错误）评估实际发生频率。
- 协议段落抽取：为新实验建立定义，不从活性表猜协议。

**验收**（v1 目标沿用，在真实数据上校准后可调整，调整需记录理由）：
- 数值 + 限定符 + 单位完全正确率 ≥ 98%；高置信度结构 InChIKey 精确匹配 ≥ 95%；
- 未标记错误数为 0，或逐条列出并说明原因；
- 未标记错误数显著低于开源工具基线；
- DACRA 专利上分级值、Emax、化合物角色正确入库，缺失语义不被合并。

### I3c 复核队列界面（约 2 周，可与 I3b 后半段并行）

- 原文截图（按页码与坐标）与抽取字段并排；一键确认 / 修改 / 拒绝，调用现有 `LedgerStore.review`。
- 按置信度排序（低置信度在前）；高置信度支持抽检与批量确认。
- 修改记录回流为评测数据。
- 本机最小账号：复核人身份可区分（完整账号体系仍在 I7）。

**验收**：一名化学家完成 1 份专利的复核，记录耗时，并与手工转录对比（v1 目标：缩短 ≥ 70%）。

### I2.5 真实模型 agent 首跑（1–2 周，API key 到位后，可与 I3a 并行）

- 用现有 MCP 工具，让真实模型完成 3–5 个小任务。例如：比较两个实施例的证据并说明能否比较；从给定的一页测量中提交缺失记录；解释某条关联为什么没有展示。
- 评测 agent 行为：回答中的数字是否都来自工具结果（沿用引用审计）；有没有尝试确认记录或绕过工具；是否正确对待限定值和缺失值；越界行为计数。
- 每次运行保存记录并重放；统计 token 与成本。

**验收**：越界行为数与引用可解析率有记录；所有运行可重放；据此修订工具描述，并写入 I6 的设计。

### I2.6 结构检索入口（1–2 周，ChEMBL 部分无外部依赖；SureChEMBL 部分待访问与许可核实后约 +1 周）

**状态（2026-09-28）**：开发完成，待在线核对（见本节末尾的进度与第 8 节）。

目标：输入一个结构，找到含有相同、相似或共同子结构化合物的专利和文献，并接入现有“分子 → 测量 → 来源文档 → 专利候选”的追溯链。

- **检索方式**：精确（现有，按 InChIKey）、相似性（Tanimoto，阈值可调，默认值在验收用例上确定并写入文档）、子结构（SMILES / SMARTS）。子结构查询过于宽泛时要求细化，不静默截断。
- **结构预处理**：RDKit 去盐、中和、互变异构标准化；页面并排显示原始结构与标准化后结构，可以关闭标准化；标准化会合并哪些形式要写明。
- **数据源**（按接入顺序）：
  1. ChEMBL 相似性与子结构检索 → 命中分子 → 复用现有测量与来源文档链路（论文 / 专利 / 待核实）；
  2. SureChEMBL 结构检索专利（先核实当前访问方式、速率限制与许可；未核实前不接入）；
  3. PubChem 化合物的专利与文献交叉引用（补充来源，结果单独标注）；
  4. 本地台账内检索（与 I5 共用实现）。
- **证据原则**：
  - 相似度只用于排序和筛选，**不作为证据**，也不暗示活性相近或属于同一研发程序；
  - 每次检索记录查询结构、标准化方式、检索方式、阈值、来源、时间和响应快照哈希，结果可以按记录重放；
  - 显示返回上限与是否截断；**零命中不等于不存在**，页面和工具结果都要写明；
  - 数据库中的“分子—文档”关联不证明该结构是某个实施例，也不证明被权利要求覆盖；
  - 加入台账只能是 `proposed`，化合物角色为 `unspecified`，不带测量值（测量走现有 ChEMBL 测量入口）。
- **工具层**：新增只读、联网的 MCP 工具 `structure_search`（参数严格校验，结果进入运行记录与重放）；agent 与页面使用同一实现。
- **页面**：SMILES 入口增加检索方式与阈值；结果列表显示相似度或匹配的子结构高亮、来源与“为什么找到”；可以从命中分子继续查看测量、来源文档和专利候选。
- **在线核对**：`phase0.tools.verify_online` 增加结构检索一项。

**验收**：
- 离线测试覆盖三种检索方式、标准化、截断与零命中提示、重放（模拟响应）；
- 以已整理的 ALK 案例为检验：用克唑替尼、洛拉替尼及台账中的实施例结构做相似性和子结构检索，记录能否找回台账中已知的论文与专利家族（已知集很小，只作为代理指标，不当作召回率）；
- 在可联网本机完成一次在线核对并记入 `docs/baseline.md`；
- SureChEMBL 部分：形成访问方式与许可的核实记录；可用时接入，并用同一用例核对专利命中。

### I2.7 目标驱动的 SAR 调研闭环（约 4–5 周，无外部数据依赖，可与 M2 并行）

目标：让药物化学家从“一个陌生结构 + 项目目标”（例如“改善细胞活性，同时控制外排”）走到“下一轮实验讨论材料”，每一步都能看到依据、范围和缺口，数字仍只由确定性代码产生。

**动机（真实案例）**：台账中 6f → 6e（酰胺 N,N-二甲基改为 N-甲基，洛拉替尼发现论文）：WT ALK Ki 22.0 → 2.8 nM（B/A 0.127），L1196M Ki 310 → 35 nM（B/A 0.113），但 MDR1 外排比（MDCK，CHEMBL3293391）7.6 → 17（B/A 2.24），人肝微粒体表观内在清除率（CHEMBL3293390）58 → 28 mL/min/kg，LogD 均为 2.1；台账中**没有 6f 的两个细胞 IC50 记录**（6e 为 116 nM 与 1665 nM）。系统现在能找出并判断这些数是否可比，但说不出“活性有利、外排不利，最该先补测 6f 的细胞 IC50”。

工作项（对应流程五步）：

- **A 项目目标与性质画像**（第 1 步）：
  - 目标由若干性质组成，每个性质指定台账中的实验 / 终点、期望方向（越低越好 / 越高越好 / 目标区间）和阈值；提供模板（如“细胞活性 + 外排”“酶活性 + 选择性”），可逐项修改。
  - 性质到实验的映射按终点类型和实验描述给出建议，**由用户确认**；映射不上的实验列出来，不静默丢弃。
  - 不做综合打分：各性质并排显示，不合成一个分数。
- **B 检索覆盖报告**（第 2 步）：
  - 汇总本次检索查了哪些来源、各自的检索方式、阈值、返回上限、是否截断、失败或未实连的来源，以及命中按来源 / 文档 / 年份的分布。
  - 列出已知缺口：未查询的来源、只有结构没有测量的专利、未抽取活性的专利。
  - 结构检索命中可直接“加入台账（待确认）”，角色为 `unspecified`、不带测量值，之后才能进入配对。
- **C 自动配对与噪声阈值**（第 3 步；从 I5 提前）：
  - 用 RDKit MMP 切分在全台账（或用户限定的文档、实验、核心、重原子变化上限）内自动找可比较的分子对；手动选对保留，取消每批 8 对的上限。
  - 噪声阈值按终点类型给默认值（如 Ki / IC50 暂以 |log10(B/A)| ≥ 0.3，即 2 倍），**标明“默认值，待化学家确认”**，可按项目修改；有重复测量时优先用实测波动。阈值内记为“未变 / 不确定”，不记为有利或不利。
  - 可比性判断沿用现有规则（同来源、同实验、精确值；限定值、重复、缺失都不计算）。
- **D 按位点的多性质证据总结**（第 4 步）：
  - 每个位点、每种替换，逐项列出目标中各性质的结果：有利 / 不利 / 未变或不确定 / 不可比 / 缺失，附分子对数和独立来源文档数。
  - 同一替换对其他性质的影响放在同一行并排显示（例如活性有利、外排不利）；相反案例单独列出。
  - 证据强弱按公开规则分级（例如：多个独立文档、同方向且超出阈值为较强；单一文档为较弱），规则写入文档，不用模型判断。
- **E 下一轮实验讨论材料**（第 5 步）：
  - **候选方向**：仍只从已记录的分子中选，列出每个目标性质的状态与证据强弱，不生成新结构。
  - **补测建议**：对“其他性质有利、某个目标性质缺失或不可比”的分子对，列出最值得补测的测量并排序，写明排序依据（缺的是哪个目标性质、影响几个分子对的判断）。
  - **合成可行性**：只列“待评估项”（例如新增立体中心、环系改变、所需片段是否在台账中出现过），不下结论；接入开源逆合成工具作为可选的第二阶段，先核实许可。
  - 导出一份讨论材料（Markdown / JSON），每个数字附来源定位；同时提供 MCP 工具，agent 与页面使用同一实现。

**原则**：目标、阈值和映射都由用户确认并记录在输出里；系统给出的是讨论材料，不是结论；所有记录仍为“待确认”。

**验收**：
- ALK 案例：以 6e 所在系列为输入、目标设为“细胞活性 + 外排”，自动配对找出 6f → 6e；多性质表显示酶 Ki 有利、MDR1 外排比不利、LogD 未变；补测建议把 6f 的细胞 IC50 排在前列并写明依据；
- 覆盖报告如实列出本地与在线来源、截断与未实连的来源；
- 默认阈值和性质映射在输出中可见、可修改，修改后结果随之变化；
- 离线测试覆盖五个工作项，浏览器测试覆盖完整五步路径；
- 1 位化学家按真实项目问题走一遍并记录意见（依赖第 3 节的访谈安排）。

**建议顺序**：A、C、D 先做（约 2.5 周，完成后即可用真实数据演示多性质取舍），再做 B、E。

**进度（2026-09-28）**：第一段（A、C、D）已完成——`phase0/sar/mmp.py`（单切 + 氢替换，台账上 18 个分子对、15 种替换）、`phase0/sar/project_sar.py`（两个目标模板、实验映射建议、目标校验、逐实验比较、证据等级、缺失列表）、`/api/project-sar` 与 `/project` 页面；测试 417 项。验收：6f → 6e 酶 Ki 有利、MDR1 外排比不利、LogD 未变、6f 细胞 IC50 缺失，均已写成测试。第一段补齐（同日）：自定义性质（从范围内任意实验组成）、目标区间方向（单边或双边、带单位换算）、按位点汇总（连接点 3 个键以内的化学环境，台账上 5 个位点，可跨文档归并同一位置）；测试 431 项。**第二段（同日完成）**：B 检索覆盖报告（各来源状态、命中与截断、本地命中文档分布、已知缺口），SureChEMBL 命中作为专利结构入台账（服务端重读化合物并核对专利关联；ChEMBL 命中沿用已有的测量入台账）；E 范围覆盖、候选方向 / 取舍 / 不利 / 证据不足分类、补测建议（固定排序规则，6f 细胞 IC50 排第一）、合成可行性待评估项（只提示，不判断）、Markdown / JSON 讨论材料；MCP 工具 `project_goal_suggest`、`project_sar_analyse`（共 17 个）；测试 439 项。**尚待**：化学家确认默认阈值、证据分级和补测排序规则并走查一次；逆合成工具（可选第二阶段）。

| 结构标准化合并了不该合并的形式（盐型、互变异构、立体） | 并排显示原始与标准化结构，可关闭标准化；合并规则写入文档 |
| SureChEMBL 接口行为依据第三方实测记录，不在官方说明中，可能变化 | 首次在线核对按实际修正适配器；失败时如实提示并保留其他来源结果；核实记录随之更新 |
| SureChEMBL 与 PubChem 的专利关联同源，被误当成独立佐证 | 并列显示、不合并；页面、工具说明和讲解材料都写明；不参与置信度计算 |
| 过宽的查询拖垮共享的公共服务，或触发限速 | 子结构至少 6 个重原子；一次只跑一个任务；轮询退避；每次只取首页；PubChem 每次最多 3 个请求 |
| 专利中自动提取的结构被当成实施例或竞品化合物 | 页面与工具说明写明“只说明结构出现在专利中”；进入证据流程必须加载原文核实 |
| 默认噪声阈值或性质映射不适合具体项目，导致有利 / 不利判断失真 | 默认值在输出中标明“待确认”，可按项目修改并记录；阈值内一律记为不确定；化学家访谈后更新默认值 |
| 讨论材料被当成结论或实验优先级决定 | 输出标题与每一节写明“讨论材料”；不做综合打分；补测排序写明依据，由化学家决定 |
| 合成可行性被系统“判断” | 第一阶段只列待评估项；逆合成工具仅作为可选的第二阶段，结果同样只作参考 |
